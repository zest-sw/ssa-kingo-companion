# 일정·보드 점검 (2026-11-04, v2.1)

기준: `docs/product/concept.md` '레퍼런스에서 가져올 기능'(Jira 보드, GitHub Projects, Things·Asana 오늘, Todoist). 화면은 `#/activities`(요약)와 `#/activities/schedule`(타임라인·보드·목록), 활동 서랍.

| 레퍼런스 → 우리 서비스 | 고치기 전 | 고친 뒤 | 무엇을 했나 |
| --- | --- | --- | --- |
| Jira 세 칸, 한 칸에 여러 상태 | 있음 | 있음 | 그대로 |
| 경고색 없음, 떨어진 신청도 끝난 것 | 있음 | 있음 | 그대로(오렌지는 '오늘'과 회고 대기 칸에만) |
| 카드: 가장 급한 마감 하나 + 상태 꼬리표 | 있음 | 있음 | 그대로 |
| 하는 중이 많으면 새 추천을 줄임 | 없음 | 약함 | 보드 '하는 중' 칸에 3개 이상이면 안내 한 줄. 추천 쪽에서 실제로 줄이진 않아 문구는 "새로 시작하기 전에 지금 것부터 살펴봐요" |
| 마감과 활동 날짜를 따로(Things·Asana) | 약함(목록은 한 칸에 섞임, 타임라인은 대기 기간만) | 약함 | 목록에 '◆ 마감'·'활동 날짜' 칸을 나눔. 타임라인 막대는 대기 기간(◆ 마감까지)만 그리고 활동 날짜 막대는 못 그림(아래 남은 것) |
| 같은 데이터를 목록·보드·캘린더로(Todoist) | 있음 | 있음 | 그대로 |
| 목록: 날짜 순·상태 묶음, 많아도 읽힘 | 약함(상태 묶음 없음, 마감순/최근순 칩) | 있음 | 보드와 같은 세 칸 묶음 + 칸 안 날짜 순, 칩 둘은 뺌, 표 머리는 스크롤해도 고정 |
| 활동 서랍: 일정·준비·실행 기록·회고가 한 흐름 | 약함(상태마다 다음 일을 안 말함) | 있음 | 단계 아래 한 줄('끝났어요. 회고를 쓰면 기록으로 남아요' 등). 마감·일정은 아래 표에만 |
| 끝난 활동은 회고를 쓰면 기록으로 | 있음 | 있음 | 그대로 |

남은 것: 타임라인 한 줄에 대기 기간(◆ 마감)과 활동 날짜 막대를 함께 그리려면 `GanttRows`(src/components)가 줄당 막대 둘을 받아야 한다(공용이라 이번엔 안 건드림). 추천 쪽에서 하는 중이 많을 때 후보를 줄이는 규칙(`src/domain/recommend*`)은 범위 밖.
