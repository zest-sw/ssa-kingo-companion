# 킹고 컴패니언 기획서 v0.5 · 에이전트 큐레이션 UX

> 원본: [Notion 기획서 v0.5](https://app.notion.com/p/155ce4d2588241b8a725aa8f29f9cb82) (2026.10.08). 대응 프로토타입: `prototype-v0.7` 태그.

## 버전과 읽는 방법
기획서 v0.4(채용 요건과 경험 연결)의 원칙을 유지하면서, 챌린지스퀘어와의 역할 분담과 인지부담 축소를 중심으로 다시 설계한 v0.5다. 대응 프로토타입은 SSA 팀 폴더의 [Figma Make v0.7](https://www.figma.com/make/DHknzG1sIEnxBdn1Pzevci)이다.
- v0.1~v0.4 기획서와 Figma v0.3~v0.6은 그대로 보존한다.
- 프로토타입은 예시 데이터와 화면 안 규칙으로만 동작한다. 실제 AI·학교 API·챌린지스퀘어 연동·저장소는 없다.

## 1. 문제 정의: 정보는 많고, 고르는 일은 학생 몫
- 2026.10.08 SKKU 비교과 가이드에 표시된 학부생 참여 가능 프로그램은 61개(대학원 28, 외국인 6)다. 채용설명회·공모전·특강·멘토링이 한 목록에 섞여 있고, 대부분 '자기주도성' 같은 넓은 역량 태그가 붙는다.
- 챌린지스퀘어 목록은 로그인 후에만 보인다. 2026-08 학생용 매뉴얼 기준 검색은 키워드, 체크박스 필터 4개(디지털배지여부·도전학기·나의 스크랩 보기·3품인증대상), 정렬 3개(신청 마감순·최신 등록순·스크랩순)이고 카드 1장에 정보가 12~13개 들어간다.
- 신청 대상은 공지 본문의 자유 텍스트에 있고, 일정 충돌 확인이 없으며, 같은 강연이 날짜별 카드로 따로 올라온다. 수강확정 여부도 학생이 다시 들어가 확인해야 한다.
- 활동이 끝나면 이수 내역·증명서·배지·후기(별점과 글, 다른 학생용)가 남는다. 활동을 자기이해로 바꾸는 장치, 개인화 추천과 추천 이유 설명은 찾지 못했다.
- 결론: 학생에게 부족한 것은 정보가 아니라 나에게 맞는 하나를 고르고, 해 보고, 의미를 남기는 과정의 수고다.

## 2. 챌린지스퀘어와의 역할 분담
챌린지스퀘어는 학교 공식 원천·신청·이수 기록이다. 컴패니언은 이를 대체하지 않고 그 위에서 고르기·챙기기·의미 만들기를 맡는 에이전트 레이어가 된다.
- 무엇을 할까: 챌린지스퀘어는 전체 목록·검색·필터 → 컴패니언은 이번 주 1개와 접어 둔 대안 2개.
- 나에게 맞나: 학생이 공지를 읽고 판단 → 에이전트가 대상·마감·시간·정원·중복을 미리 확인하고 이유를 1줄로.
- 신청: 신청은 챌린지스퀘어에서 학생이 직접(대리 신청 안 함) → 해당 프로그램 신청 화면으로 바로 연결하고, 수강확정·전날 알림은 에이전트가 챙김(연동 후).
- 하고 나서: 이수 기록·후기 → 30초 회고 → 자동 아카이브 카드 → 발견 갱신 → 다음 추천.
- 나를 알기: 역량진단(SSCA)은 별도 메뉴 → 활동 반응(한 일·에너지)이 쌓여 수정 가능한 발견으로.
- 진로: 활동 단위 → 실제 채용 공고 요건과 내 기록의 연결(v0.4 유지).

## 3. 제품 원칙 다섯 가지
1. 한 번에 하나만 보여 준다. 고르는 수고는 에이전트가 진다.
2. 이유는 내 기록으로 말한다. 일반 설명 대신 내가 남긴 말을 근거로 쓴다.
3. 결정은 학생이 한다. 바꾸기·쉬기·별로예요는 언제나 한 번에 된다.
4. 하고 나면 30초. 쓰기 대신 고르기로 기록한다.
5. 발견은 가설이다. 맞아요·아니에요로 학생이 정하고, 근거가 바뀌면 다시 묻는다.

## 4. 핵심 루프: 받기 → 하기 → 남기기 → 알게 되기
- 받기(월요일 아침 브리핑): 에이전트가 수집·중복 제거·조건 확인 후 1개를 추천한다. 화면에는 이유 1줄과 사실 3개(언제·얼마나·마감)만 둔다. 학생은 '이걸로 할게요' 한 번.
- 하기: 남은 일을 '챌린지스퀘어에서 신청하기' 하나로 보여 준다. 수강확정과 전날 저녁 알림은 에이전트가 챙긴다.
- 남기기(활동 다음 날): 가장 많이 한 일(칩) → 끝난 뒤 에너지(3단계) → 한마디(선택). 탭 3번이면 끝난다.
- 알게 되기: 기록 카드 생성, 같은 유형 근거 2개 이상이면 발견 생성·갱신, 공고 요건 연결, 다음 주 추천 반영을 완료 화면 4줄로 보여 준다.
- 못 갔어요·쉬기: 기록을 남기지 않고 다음 주로 넘어간다. 연속 기록 압박이나 불이익은 두지 않는다.

## 5. 추천 로직 (프로토타입 규칙이며 운영 모델 아님)
- 하드 필터: 마감 지남 → 신청 대상 아님 → 학생이 고른 시간·방식 초과 → 이미 했거나 별로라고 한 활동. 단계별 개수를 '고른 방법' 시트에 그대로 공개한다.
- 가점: 관심 분야 +3, 에너지가 생긴 활동 유형 +2, 맞다고 확인한 발견과 같은 유형 +2, 관심 직무 공고 요건 연결 +1(아직 기록이 없는 요건이면 +1.5), 안 해 본 분야 +1('아직 모르겠어요'면 +2), 마감 3일 이내 +0.3.
- 감점: 에너지가 떨어진 유형 −1.5, 별로라고 한 분야 −4, '어려워 보여요' 이후 2단계 이상 −2, 지난주와 같은 분야 −2(필터 버블 방지).
- 대안 2개: 다음 점수 1개와 다른 분야 1개. '더 가볍게', '새로운 분야', '온라인으로'처럼 차이만 표시한다.
- 모드: 확인한 발견이 없으면 '넓게 탐색 중', 하나라도 맞다고 하면 '좁혀 가는 중'. 화면에 한 단어로 보여 준다.
- 설정에서 회고 활용을 끄면 회고를 발견·추천에 쓰지 않는다. 채용 연결을 끄면 진로 근거를 쓰지 않는다.

## 6. 정보 구조: 3개 탭
- 이번 주 — 지금 뭘 하면 돼? 추천 1개, 또는 예정·회고할 활동 한 장만.
- 기록 — 내가 뭘 했지? 자동으로 쌓이는 카드, 직접 추가, 고치기·지우기.
- 나 — 나는 어떤 사람이지? 발견(최대 3개) → 가까워지는 방향(공고 근거는 접어 둠) → 더 보기(6축, 관심·시간, 데이터·개인정보, 설계 메모, 프로토타입 정보).
- v0.6의 4개 메뉴에서 활동 탐색 전체 목록을 뺐다. 전체 목록은 챌린지스퀘어에 있으므로 중복하지 않는다.
- 그래프·6축·공고 상세는 지우지 않고 필요할 때 펼치는 깊이로 옮겼다.

## 7. HCI 원리 → 설계 결정
- Hick–Hyman 법칙, 선택 과부하(Iyengar & Lepper 2000): 선택지가 많을수록 결정이 늦어지고 실행이 줄어든다 → 추천 1개를 먼저, 대안은 2개까지 접어 둠.
- 인지부하 이론(Sweller 1988), 작업 기억 4±1(Cowan 2001): 과제와 무관한 정보는 외재적 부하 → 카드에 이유 1줄과 사실 3개만, 반복 안내 문구는 시트 안으로.
- 점진적 공개(Nielsen): 근거·원문·확인 항목은 '왜 이 활동인가요'에서만 보여 줌.
- 기억보다 알아보기(Nielsen 휴리스틱 6): 회고는 빈칸 쓰기 대신 칩 선택, 예시 문장 칩 제공.
- 상태 보이기와 평가 간극(Norman), 종결·되돌리기(Shneiderman 황금률): 4단계 흐름 표시, 기록 뒤 바뀐 것 4줄, 대부분의 행동에 되돌리기.
- 인간-AI 상호작용 가이드라인(Amershi et al. 2019), 혼합 주도 인터페이스(Horvitz 1999): 왜 했는지 설명(G11), 쉬운 수정(G9)·무시(G8), 세분화된 피드백(G15), 전역 제어(G17), 반응 학습(G13), 불확실하면 단정하지 않기(G10, 정원 미확인은 경고 한 줄).
- 기본값 효과(Johnson & Goldstein 2003), 자기결정성 이론(Ryan & Deci 2000): 추천은 좋은 기본값으로 두되 바꾸기·쉬기를 같은 깊이에 두어 자율성을 지킴.
- Fogg 행동 모델(2009): 능력은 1탭으로, 계기는 월요일 브리핑과 활동 다음 날 체크인으로.
- 조용한 기술(Weiser & Brown 1996): 알림은 주 2회(브리핑·회고)와 신청한 활동의 전날 알림만.
- 정보 향기(Pirolli & Card 1999): 추천 이유에 학생 자신의 기록 제목과 표현을 씀.
- 노동 착시(Buell & Norton 2011): 시작할 때 확인 → 맞추기 → 고르기 과정을 짧게 보여 주고, 걸러 낸 개수를 공개해 신뢰를 높임.
- Fitts 법칙과 터치 대상: 주요 버튼은 54px 높이·전체 폭, 모든 터치 대상 44px 이상.

## 8. v0.6 → v0.7 측정 비교
측정은 프로토타입 구조에 대한 것이며 실제 사용자 실험 결과가 아니다. 1440×900에서 첫 화면에 보이는 버튼·링크·입력·탭 수와 본문 텍스트 길이를 스크립트로 계산했다.
- 첫 화면 조작 요소: 52개 → 9개(−83%).
- 첫 화면 본문 텍스트: 2,498자 → 319자(−87%), 섹션 5개 → 1개.
- 첫 화면 본문의 '예시·미확인·아님·않습니다' 표현: 14회 → 0회. 필요한 주의는 '정원은 신청할 때 확인' 한 줄.
- 이번 주 활동 정하기: v0.6은 활동 탐색 → 카드 비교 → 상세 → 저장(결정 버튼 없음) → v0.7은 '이걸로 할게요' 1탭.
- 회고 남기기: v0.6은 약 6번 클릭과 텍스트 3칸 → v0.7은 3탭, 타이핑 0.
- KLM 추정(Card, Moran & Newell 1980; 생각 1.35초, 가리키기 1.1초, 클릭 0.2초, 타자 0.28초/자, 칸당 20자 가정, 읽기 시간 제외): 활동 정하기 약 11초 → 약 2.7초, 회고 약 35초 → 약 9초.
- 390×844 모바일: 가로 넘침 없음, 주요 버튼이 첫 화면 안(627–681px), 24px 미만 터치 대상 0개.

## 9. v0.6 휴리스틱 평가에서 고친 것
- 시스템 상태: 분석·확인 상태가 여러 곳에 흩어짐 → 4단계 흐름 하나로 통일.
- 미니멀 디자인: 카드마다 반복되던 면책 문구 → 프로토타입 정보 시트 한 곳.
- 사용자 통제: 카드마다 있던 연결 확인·수정·제거 등 버튼 5개 → 맞아요·아니에요·근거 보기 3개.
- 인식 대 회상: 회고 텍스트 입력 3칸 → 칩 선택.
- 일관성: 활동 탐색·채용 탭·그래프의 서로 다른 강조 방식 → 카드 1종(제목-이유-사실-행동).

## 10. 데이터·개인정보 (v0.4 원칙 유지)
- 공고·프로그램 정보는 공통 데이터, 기록·회고·발견·추천 이력은 학생별 비공개.
- 챌린지스퀘어 이수 내역 가져오기는 선택 동의다. 학교 동의 절차와 운영 API가 정해지기 전에는 연결하지 않는다.
- 기록을 고치면 그 기록을 쓰는 발견의 확인이 해제되고, 지우면 발견 근거와 공고 연결에서 함께 빠진다.
- 회고 활용·채용 연결을 끄면 추천에서도 바로 빠진다. 내보내기와 전체 삭제를 제공한다.
- 학번·이름·성적은 추천 점수에 쓰지 않고, 다른 학생과 비교하는 점수·순위는 만들지 않는다.

## 11. 남은 과제와 검증 계획
- 사용자 테스트: 재학생 6~8명, 과제 3개(이번 주 활동 정하기·회고 남기기·발견 확인), 결정 시간·오류·SUS·NASA-TLX(Raw)·인터뷰.
- A/B 비교: 추천 1개+대안 2개 대 목록 5개. 수락률, 결정 시간, 4주 참여 지속, 회고 완료율.
- 추천 품질: 실제 프로그램 코퍼스와 학생 피드백으로 규칙 기준선 대비 하이브리드·LLM 재정렬 비교(Recall@K, NDCG@K, 조건 위반률).
- 연동: 챌린지스퀘어 데이터 제공 방식, 신청 딥링크, 수강확정 상태 조회 권한을 학생성공센터와 협의.
- 역량 체계: 학교 5대 학생성공역량(자기주도성·글로벌·시민의식·융합·기업가정신)과 프로토타입 6축을 맞추는 방법 정리.
- 차단: 실제 학생 데이터·학교 API·운영 권한·동의 범위가 아직 정해지지 않았다.
