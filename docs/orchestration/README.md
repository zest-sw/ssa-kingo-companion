# 오케스트레이션

지휘 에이전트(**Aside**) 하나가 사용자와 대화하고, 실제 개발은 **Orca** 작업 공간(worktree)마다 Claude 워커가 한다. 사용자가 "~해줘"라고 하면 개발, 검증, 피드백, 병합까지 알아서 간다.

## 역할

| 역할 | 누가 | 하는 일 |
| --- | --- | --- |
| 지휘 | Aside | 스코프 판단, 작업 쪼개기, 워커 dispatch, 감시, 검수, 브라우저 QA, 병합, 보고 |
| 기반 | Orca 워커 (opus) | 앱 틀, 토큰, 공용 컴포넌트, 도메인 추출. 순차로 한 명만 |
| 화면 | Orca 워커 (sonnet) | 화면 묶음 하나. 병렬로 여러 명 |
| 리뷰 | 읽기 전용 서브에이전트 | 끝난 브랜치의 diff를 보고 문제만 보고. 코드는 안 고친다 |

세부 지침은 `agents.md`, 지휘 절차는 `conductor.md`, Orca 사용법은 `orca.md`.

## 원칙

1. 사용자와 대화하는 건 지휘자뿐이다. 워커는 지휘자에게만 보고한다.
2. 워커는 자기 작업 공간, 자기 폴더만 만진다. 겹치는 파일을 같이 만지는 병렬은 하지 않는다.
3. 끝까지 간다. 구현, 자체 검증, 리뷰, 브라우저 QA, PR, CI, 병합까지. 문제가 나오면 재작업을 바로 보낸다.
4. 같은 문제로 3번 실패하면 그때만 사용자에게 넘긴다.
5. 기준은 Notion '서비스 철학·컨셉 정리'(`docs/product/concept.md`)다. 옛 기획과 충돌하면 기준 문서가 이긴다.
