# 데스크톱 웹 명세

기준: `docs/product/concept.md`, `docs/product/decisions.md` (2026-10-12 4차 리뷰: 앱이 아니라 데스크톱 웹, 글씨는 줄이고 그래프·도표·그림, 토스처럼 간결하게, 성균관대 UI 색 네이비·그린·오렌지).
목업(`docs/design/mockups/`)은 **참고용**이다. 확정이 아니고 기준 문서가 이긴다.

## 1. 틀

2026-10-29 리디자인: "둥글고 유아틱하다"는 피드백으로 업무 도구처럼 정돈된 톤(Linear, Vercel·Stripe 대시보드, 토스 비즈니스 화면)으로 바꿨다.

- 왼쪽 사이드바 220px 고정 + 오른쪽 본문. 본문은 가로를 채운다(좁은 폭 상한을 두지 않는다). 읽을 글 단락만 72ch 로 제한한다.
- 사이드바: 로고(은행잎) + 킹고 컴패니언 / 메뉴 7개(높이 34px, 아이콘 16px) / 맨 아래 학생 카드와 그 옆 **톱니바퀴(설정)**.
- 메뉴: 홈, 추천(새 후보 개수 배지), 내 활동, 기록, 나의 분석, 도전 과제, 친구. 활성 메뉴는 옅은 회색 바탕 + 진한 글자(테두리 없음).
- 설정(`#/settings/<id>`, 기본 `profile`): 왼쪽 하위 메뉴, 오른쪽 내용. 프로필·추천 조건 / 공개 범위 / 데이터·개인정보 / 알림 / 프로토타입 정보. 예전 `#/friends/visibility` 는 `#/settings/visibility` 로 넘어간다. 항목 하나에 붙은 스위치(기록 카드의 '추천에 쓰기' 등)는 그 자리에 둔다.
- 본문 머리: 위에 작은 회색 글씨(학기 또는 구역 이름, 13px), 그 아래 제목(24px). 오른쪽에 그 화면의 주요 행동 1~2개.
- 지원 폭: 1280 / 1440 / 1920 에서 완성. 1024 에서는 사이드바를 아이콘만 남기고 본문이 깨지지 않으면 된다. 모바일은 이번 범위가 아니다.
- 상세는 모달이 아니라 **오른쪽 서랍(drawer, 폭 480px)** 이 기본이다. 확인이 필요한 짧은 질문만 가운데 모달.
- 라우팅은 해시(`#/home`, `#/recommend`, ...). 새로고침해도 같은 화면이 열린다.
- 전역 상태는 한 곳(`src/app`)에서 공급하고, 화면은 필요한 조각만 읽는다. 저장소는 없다. 새로고침하면 예시 상태로 돌아가는 걸 기본으로 하되, 학생이 고른 것(프로필, 공개 범위, 데이터·알림 설정, 추천 선택과 다시 볼 날, 신청 준비로 만든 활동과 체크, 회고 초안, 분석 답)은 `localStorage` 한 키(`src/app/storage.ts`)에 둔다.

## 2. 토큰 (`src/styles/tokens.css`)

컴포넌트와 화면에는 값을 직접 쓰지 않고 토큰만 쓴다. 무채색이 바탕이고 색은 의미가 있을 때만 쓴다.

| 토큰 | 용도 | 값 |
| --- | --- | --- |
| `--green-900` (`--primary`) | 주 버튼(한 가지), 확인 점, 개발 분야 | #1e3b2e |
| `--lime-500` | 창업·기획 분야 점·선. 넓은 면에 칠하지 않는다 | #8ba860 |
| `--navy-900` | AI·데이터 분야, 포커스 링 | #1d2b4f |
| `--orange-500` (`--accent`) | 오늘·마감 임박에만(멘토링 분야 점 포함) | #d4682c |
| `--bg` / `--surface` / `--surface-hover` | 바탕(아주 옅은 회색 한 가지) / 카드 / 눌러지는 행의 호버 | #f8f9fa / #ffffff / #f4f5f7 |
| `--line` / `--line-strong` | 면을 나누는 1px 선 / 입력·보조 버튼 테두리 | #e6e8eb / #d3d7dc |
| `--ink` / `--ink-muted` / `--ink-subtle` | 글자 / 보조 / 흐린 글자 | #111418 / #5e6570 / #8a909a |

- **반지름**: `--radius-sm`·`--radius-md` 4px(버튼, 입력, 칩, 배지, 탭, 행), `--radius-lg` 6px(카드, 패널, 서랍, 모달), `--radius-xs` 2px(진행 막대, 자리 표시 줄). `--radius-full`(알약)은 상태 점과 아바타에만 쓴다.
- **면과 선**: 카드는 흰 바탕 + `--border`(1px `--line`), 안쪽 여백 20px(`--space-5`), 목록 행은 12px 안팎. 큰 색 면 대신 선으로 나눈다. 그림자(`--shadow-overlay`)는 서랍·모달·토스트에만.
- **글자**: Pretendard Variable(jsDelivr dynamic-subset, `index.html`), 못 불러오면 시스템 한글 글꼴. 크기 12 / 13 / 14(본문) / 16(카드 제목) / 18(서랍 제목) / 20 / 24(화면 제목) / 28(큰 숫자). 굵기 `--weight-bold` 600, 화면 제목만 `--weight-heavy` 700. 제목 자간 `--tracking-tight` -0.02em. 숫자는 전역 `tabular-nums`.
- **크기**: 버튼·입력 `--control-h` 36px, 작은 버튼·칩·클릭 대상 최소 `--hit-min` 32px, 메뉴 항목 `--nav-item-h` 34px, 개수 배지 `--count-h` 18px. 아이콘 16px·선 1.5px(`--icon`), 작은 것 14px, 큰 것 20px.
- **움직임**: `--duration` 150ms + `--ease`. 튀는 애니메이션은 쓰지 않는다.
- 탭(`Tabs`)은 밑줄 탭, 보기 전환(`SegmentedControl`)은 회색 홈에 흰 칸. 빈 상태 아이콘은 장식 원 없이 20px 선 아이콘만.
- 분야 색은 의미가 고정이다: 개발=진한 그린, AI·데이터=네이비, 창업·기획=연두, 멘토링=오렌지, 글로벌=회색. 색만으로 구분하지 않고 라벨을 함께 둔다.
- AI 추정은 옅은 점선 테두리/점선 점, 학생이 확인한 것은 채운 점. 불확실한 표현을 색이 아니라 선 모양으로 전한다.

## 4. 화면별 요점 (기준 문서에서)

**추천.** 가장 추천 하나를 크게. 학생이 누르는 건 '신청 준비', '나중에 보기', '관심 없음' 셋. 다른 대안은 몇 개인지만 아래에 알리고, 누르면 열린다. 비교 화면은 같은 항목끼리 나란히 놓고 **적합도 점수는 보이지 않는다**. 추천 이유는 일치한 태그와 근거 기록으로 만든 템플릿 한 줄. 순위 규칙은 `src/domain` 의 기존 규칙(v0.7 `rank`)을 쓰되 점수는 화면에 안 낸다.
**신청 준비.** 에이전트가 신청 대상 확인, 일정 등록, 신청서 초안을 맡는다. 학생은 남은 일만 하고 '이대로 신청'(승인), '고쳐 줘', '안 할래'로 답한다. 남은 준비가 있으면 '이대로 신청'은 열리지 않는다. 실제 신청은 학생이 챌린지스퀘어에서 직접 한다는 한 줄을 둔다. 실제 연동은 없으니 예시 링크로 둔다.
**내 활동 보드.** 한 칸에 여러 상태를 묶는다(할 것: 신청 준비·결과 대기). 떨어진 신청도 경고색 없이 '끝난 것'에 둔다. 우선순위 숫자·완료 속도·경고색 없음. 끝난 활동의 '회고 쓰기'가 회고 인터뷰로 바로 열린다.
**회고 인터뷰.** 경량 LLM 이 상황별 대화 스키마(질문 순서, 끝내는 조건)로 묻는 흉내를 스크립트로 구현한다. 순서는 상황 → 역할 → 한 일 → 결과 → 배운 점 → 다음에 해 볼 것. 상황은 에이전트가 먼저 채우고 빠진 것만 묻는다. 답이 짧으면 한 번 더 묻는다. 수치는 학생이 말한 것만 적는다. 위쪽 단계 칩, 오른쪽 기록 카드에 답이 채워진다. 기록 카드에는 '학교 확인'/'직접 입력', 공개 범위(기본 나만 보기), '추천에 쓰기' 스위치.
**기록 보관함.** 학기·분야로 모아 보기. 카드마다 공개 범위와 추천 반영을 고른다.
**나의 분석.** 테크 트리: 가로줄이 분야, 왼쪽에서 오른쪽이 활동 유형(들어 보기, 해 보기, 만들기, 나누기). 테두리만 있는 칸은 지금 신청할 수 있는 추천 후보, '?'는 안 해 본 분야. 유형은 실력 단계가 아니다. 완성률 없음, 나만 본다. 경험 지도: 점선은 학생이 확인하기 전의 AI 추정. 관심 흐름: 학기별 슬라이더, 활동 없는 학기도 경고하지 않는다. 나의 강점: 내 생각과 기록이 다른 강점을 따로. 발견은 질문 카드('맞아요/아니에요')이고 확인한 것만 추천에 쓴다. 역량은 점 행으로 보여 주고 육각형 차트는 쓰지 않는다.
**도전 과제.** 레벨·점수·순위 없음. 숨은 과제는 조건 없이 희귀도(흔함·드묾·희귀)만, 일부는 힌트. 진행도 막대(2 / 3). 전시할 과제는 학생이 고른다. 총 개수와 완료율은 다른 사람에게 안 보인다. 달성하면 무엇을 잘했는지 한 줄. 예시 과제는 `concept.md` 의 표를 쓴다.
**친구.** 프로필은 기본 비공개. 비공개면 친구 찾기·팀원 모집·명예의 전당을 못 쓴다(잠금 안내가 아니라 '공개하면 열려요' 한 화면). 공개 범위(설정 → 공개 범위)는 공개하면 열리는 기능과 보이는 것을 한 화면에. 회고와 전시할 과제는 고른 것만. 발견·역량 근거는 항상 나만. 민감한 활동은 기본으로 빠진다. 팀원 모집은 대회·해커톤·공모전에 글을 올리고 같은 기회에 관심 표시한 공개 학생에게 먼저 보인다. 명예의 전당은 순위·점수 대신 선정 이유와 거쳐 온 활동을 보여 주고 내 기록과 나란히 비교하지 않는다. 선정 기준·운영 주체는 미정이라 '검토 중' 표시를 둔다.

## 5. 아직 정하지 않은 것 (정한 척 구현하지 않는다)

추천 후보 개수(지금은 1 + 대안 2), 역량 체계(목업의 5대 역량은 예시), 보드 상태 이름, 테크 트리 분야·유형 기준, 회고 알림 시점·횟수, 명예의 전당 선정 기준. 화면에서는 예시 값으로 두고 '예시'임을 프로토타입 정보에서 밝힌다.

## 6. 만들지 않는 것

점수·레벨·XP·순위표, 교과 학습 지원(코스 에이전트 몫), 대리 신청, 실제 AI·학교 API·챌린지스퀘어 연동, 로그인.
