# 데스크톱 웹 명세

기준: `docs/product/concept.md`, `docs/product/decisions.md` (2026-10-12 4차 리뷰: 앱이 아니라 데스크톱 웹, 글씨는 줄이고 그래프·도표·그림, 토스처럼 간결하게, 성균관대 UI 색 네이비·그린·오렌지).
목업(`docs/design/mockups/`)은 **참고용**이다. 확정이 아니고 기준 문서가 이긴다.

## 1. 틀

2026-10-29 리디자인: "둥글고 유아틱하다"는 피드백으로 업무 도구처럼 정돈된 톤(Linear, Vercel·Stripe 대시보드, 토스 비즈니스 화면)으로 바꿨다.

- 왼쪽 사이드바 220px 고정 + 오른쪽 본문. 본문은 가로를 채운다(좁은 폭 상한을 두지 않는다). 읽을 글 단락만 72ch 로 제한한다.
- 사이드바(v2.6, `docs/design/ia-navigation.md` 1절): 로고(은행잎) + 킹고 컴패니언 / 메뉴 4개 1단 고정(높이 38px, 낮은 화면 36px, 아이콘 16px) / 맨 아래 **학생 카드(아바타 + 학과·학년, 전체가 `#/profile` 링크, 프로필 화면에서 활성)**와 그 옆 **톱니바퀴(설정)**. 사이드바가 유일한 이동 수단이다.
- 메인 메뉴 4개: 홈, 추천(새 후보 개수 배지), 내 활동, 나의 분석. 하위 6개: 내 활동 › 일정·기록 / 나의 분석 › 테크 트리·경험 지도·관심 흐름·나의 강점. 프로필(친구·팀원 모집·명예의 전당은 그 요약 카드로만)은 메뉴가 아니라 왼쪽 아래 학생 카드로 연다. 트리는 `NAV`(`src/app/router.ts`) 한 곳에 있다.
- 메뉴는 펼치거나 밀지 않는다(1단 고정, 결정 2026-11-04). 하위 화면은 페이지 머리 아래 구역 탭(`SectionTabs`)이 맡고, 사이드바는 그 구역 항목에 지금 위치를 표시한다.
- **사이드바는 본문보다 한 단계 물러난다**(v2.6, Linear 2026-03 'A calmer interface'): 바탕은 본문과 같은 `--bg` + 오른쪽 1px 선. 지금 항목은 면을 칠하지 않고 왼쪽 2px 막대(`--nav-mark`) + 600 + `--text`. 나머지 항목 글자·아이콘은 `--text-sub` 400, hover 는 아주 옅은 바탕(`--nav-hover-bg`), 누르면 `--surface-press`. 학생 카드·설정 톱니도 같은 규칙(지금이면 왼쪽 막대). `aria-current` 는 그 화면이면 `page`, 그 아래 하위·흐름 화면이면 `location`.
- 폭이 좁아도 아이콘만 남기지 않는다. 1279px 아래 176px, 1099px 아래 148px 로 폭만 줄이고 글자는 그대로 둔다.
- 설정(`#/settings/<id>`, 기본 `profile`): 왼쪽 하위 메뉴, 오른쪽 내용. 프로필·추천 조건 / 공개 범위 / 데이터·개인정보 / 알림 / 프로토타입 정보. 예전 `#/friends/visibility` 는 `#/settings/visibility` 로 넘어간다. 항목 하나에 붙은 스위치(기록 카드의 '추천에 쓰기' 등)는 그 자리에 둔다.
- 본문 머리: 제목(24px)과 오른쪽 주요 행동 1개(보기 전환 세그먼트는 여기). 뒤로 버튼은 없다. 빵부스러기는 흐름 화면에만 한 줄.
- 지원 폭: 1280 / 1440 / 1920 에서 완성. 1024 에서는 사이드바 폭만 줄고(148px) 본문이 깨지지 않으면 된다. 모바일은 이번 범위가 아니다.
- 상세는 모달이 아니라 **오른쪽 서랍(drawer, 폭 480px)** 이 기본이다. 확인이 필요한 짧은 질문만 가운데 모달.
- 라우팅은 해시(`#/home`, `#/recommend`, ...). 새로고침해도 같은 화면이 열린다.
- 전역 상태는 한 곳(`src/app`)에서 공급하고, 화면은 필요한 조각만 읽는다. 저장소는 없다. 새로고침하면 예시 상태로 돌아가는 걸 기본으로 하되, 학생이 고른 것(프로필, 공개 범위, 데이터·알림 설정, 추천 선택과 다시 볼 날, 신청 준비로 만든 활동과 체크, 회고 초안, 분석 답)은 `localStorage` 한 키(`src/app/storage.ts`)에 둔다.

## 2. 토큰과 모양: [`DESIGN.md`](../../DESIGN.md)

색·글자 단계·간격·반경·그림자·선 모양(점선 두 뜻)·지금 위치 표시·부품 목록·움직임은 저장소 루트 `DESIGN.md` 가 기준이다(v2.9, 2026-11-06). 값의 실체는 `src/styles/tokens.css`. 여기에는 그 파일에 없는 동작만 남긴다.

- **토스트**: 한 번에 하나, 5초 뒤 사라지고 마우스를 올리거나 버튼에 초점이 있으면 멈춘다. 되돌릴 수 있으면 동작 버튼 하나(`toast(msg, { actionLabel: '되돌리기', onAction })`). `aria-live=polite`.
- **칸 안 스크롤 흐림**: `Panel` 몸통이 넘치면 더 있는 쪽 가장자리만 옅게 흐린다(`useScrollFade`, TDS 메뉴 레퍼런스).
- 검사: `npm run audit:copy`(보이는 글자의 기호·금지어·가운뎃점 사슬, `.qa/copy/report.md`), `npm run audit:design`(avoid-ai-design 스캐너, 출력만).

## 2-1. 다이어그램 부품과 이동 틀 (v0.9, `docs/design/ia-navigation.md`)

모두 `src/components` 에서 가져오고 `#/_kit` 에 기본·빈 데이터·아주 긴 라벨·많은 항목으로 그려 두었다. 외부 차트 라이브러리 없이 HTML·CSS 로 그린다. 위치는 %, 폭(ResizeObserver)은 눈금 간격과 줄 나누기에만 쓴다. 계산은 `diagram/geometry.ts`(테스트 있음).

- **조각은 모두 버튼이다.** 점·막대·노드는 `Piece`(`<button>`)라서 클릭·Enter·Space·포커스 링이 저절로 된다. `aria-label` 에 이름과 값(날짜·개수)을 넣는다. 보이는 모양이 작아도 누르는 칸은 `--hit-min`(32px). hover·포커스 때 값 한 줄 툴팁, 그림 가장자리 조각은 툴팁을 안쪽으로 붙인다.
- **색과 모양.** `tone` 은 분야 묶음(`dev`·`ai`·`plan`·`mentor`·`global`·`other`) + `accent`(오늘·임박) + `ink`(마감 ◆·발표 ○처럼 분야와 상관없는 표시) + `muted`. 모양 클래스(`ui-dg-mark--dot|ring|dashed|diamond|circle|fill|hatch|faded|today`)를 그림과 `Legend` 가 함께 써서 생김새가 늘 같다. 새 토큰은 `--dg-*`.
- **빈 상태.** 목록을 받는 부품은 `empty`(다음 행동 문장)를 꼭 받는다.

| 부품 | 쓰는 법 | 메모 |
| --- | --- | --- |

모든 그림은 `label`(그림 전체 이름)과 선택 표시용 `selectedId?` 를 받는다.

**머리와 위치(v1.0).** `PageHeader` 는 제목 + 주 행동 1개. 사이드바에 있는 화면은 제목만 둔다(위치는 사이드바가 보여 준다). 흐름 화면(신청 준비, 회고 인터뷰)만 `parent={parentLink('activities/records')}` 로 빵부스러기 '부모 › 이 화면' 한 줄을 그리고, 부모 칸이 돌아가는 유일한 길이다. 뒤로 버튼과 하위 화면 안의 탭(사이드바 항목을 다시 부르는 것)은 없다. 흐름 화면은 열릴 때 맨 위에서 시작하고 제목에 포커스.

**진입점은 하나.** 한 화면 안에서 같은 목적지로 가는 링크·버튼·탭은 1개 이하(사이드바 제외). 남길 하나는 내용이 붙은 쪽(요약 카드, 할 일 항목). `npm run audit:entries`(`src/app/audit/entries.test.tsx`, `npm run check` 에도 포함)가 경로마다 앱을 그려 목적지별로 센다. 버튼은 눌러서 `navigate()` 를 센다. `replace` 로 부른 이동(그만두기 뒤 돌아가기)과 질문 칸(`role="search"`)은 세지 않는다. 새 경로를 만들면 `CASES` 에 더한다.

**요약 카드.** 요약 화면(내 활동, 나의 분석, 프로필)의 카드는 `SummaryCard`(`title`, `sentence`, `value?`, `badge?`, `aid?`, `href?`). 카드 전체가 하위 화면 링크이고, `sentence` 는 그 학생의 상태에서 계산한 핵심 문장 한 줄, `aid` 는 문장 옆 작은 보조 그림(누르는 요소 없음). `href` 가 없으면 누르지 않는 카드.

**경로.** 메뉴 트리 `NAV`(`src/app/router.ts`)가 경로 표다. 화면은 `sub` 를 받는다. `navMatch(route)` 는 지금 위치(메인·하위·흐름 여부), `parentLink(path)` 는 빵부스러기 첫 칸.

| 경로 | 화면 |
| --- | --- |
| `#/home` | 홈 |
| `#/recommend`, `#/recommend/<id>` | 추천 한 화면(탭: 추천 활동 · 전체 기회). `<id>` 는 같은 목록 위에 그 기회의 가운데 모달을 연 채로(공유 가능한 주소) |

| `#/settings/<id>` | 설정 |

옛 경로는 `MOVED` 로 새 경로에 넘긴다(주소도 바꿔 둔다): `#/records`·`/archive` → `#/activities/records`, `#/records/interview/*` → `#/activities/records/interview/*`, `#/activities/board`·`/list` → `#/activities/schedule`, `#/challenges/*` → `#/profile`, `#/friends` → `#/profile`, `#/friends/profile` → `#/profile/friends`, `#/friends/recruit`·`/hall` → `#/profile/…`, `#/friends/visibility` → `#/settings/visibility`, `#/recommend/list`·`/compare` → `#/recommend`.

**상태 보존.** 요약·목록 화면에서 `const [sel, setSel] = useOverviewState('activities/records', 초기값)`. 화면 경로별 선택은 탭(sessionStorage)에 남고, 그 아래 흐름 화면에서 돌아오면(빵부스러기·브라우저 뒤로 가기) 스크롤도 되살린다.

**공용 서랍.** `openEntity({ kind: 'opportunity' | 'activity' | 'record', id })` 를 어디서 불러도 서랍 하나가 열린다(React 밖 콜백에서도 됨). 화면이 `registerEntityView(kind, ({ id, onClose }) => <기존 서랍 … />)` 로 기존 서랍을 등록하면 그게 열리고, 등록 전에는 기본 서랍(요약 몇 줄 + '자세히 보기')이 열린다. 화면을 옮기면 닫힌다.

## 4. 화면별 요점 (기준 문서에서)

**추천.** 가장 추천 하나를 크게. 학생이 누르는 건 '신청 준비', '나중에 보기', '관심 없음' 셋. 다른 대안은 몇 개인지만 아래에 알리고, 누르면 열린다. 비교 화면은 같은 항목끼리 나란히 놓고 **적합도 점수는 보이지 않는다**. 추천 이유는 일치한 태그와 근거 기록으로 만든 템플릿 한 줄. 순위 규칙은 `src/domain` 의 기존 규칙(v0.7 `rank`)을 쓰되 점수는 화면에 안 낸다. v2.1(2026-11-04): 후보 목록은 '가장 추천' 1개와 '대안 n개' 두 묶음. 고르기 카드에 '신청 준비를 누르면 에이전트가' 맡을 일(신청서 초안·일정 등록·남은 마감) 한 줄. 자세히에는 '에이전트가 확인했어요'(신청 대상·일정 겹침, 줄마다 확인에 쓴 정보), 근거 서랍에서 기록 근거마다 '추천에 쓰기' 스위치(고려대 AI선배)와 '관심·목표 바꾸기' 링크. 기록이 없는 학생은 목표 글이 가리키는 분야면 '목표', 고른 관심 분야 모집이 이번 주 없으면 그 사실, 탐색은 '처음 해 보는 …'으로 설명한다(`traceNodes` newcomer). v2.3(2026-11-04): 머리 아래 탭 두 개 [추천 활동] [전체 기회 n]. '비교 표' 이름과 보기, 옆 고른 후보 카드 2열, 별도 자세히 화면은 없앴다. 두 탭 모두 같은 행: 제목 · 종류 · 주최(추천 활동은 여유/빠듯) · '얻는 것' 칩 2~3개(상금·채용·증명 먼저) · 왜 나에게 한 줄(추천만) · D-n(3일 안만 오렌지). 가장 추천은 행 왼쪽 선. 전체 기회 위 한 줄은 종류 칩(전체 · 채용 · 특강 · 해커톤 · 대회·공모전 · 교육·캠프 · 동아리·학회 · 봉사 · 멘토링 · 글로벌, 데이터에 있는 것만, 개수와 함께), 목록 머리 오른쪽에 마감순/새로 열린 순. 추천한 기회는 '추천' 꼬리표. 행을 누르면 `#/recommend/<id>` 로 바뀌고 같은 목록 위 가운데 모달(Modal size=wide): 머리(종류·추천·주최·D-n), 하는 일, 사실 4칸, 얻는 것 전부(종류별 줄, '모집글에 적힌 것만'), 에이전트가 확인했어요, 추천이면 왜 추천했나 도식 + 근거 기록 접기(추천에 쓰기 스위치), 아래 신청 준비 · 나중에 보기 · 관심 없음 · 모집글 원문. Esc·바깥·닫기로 목록에 돌아간다. 다른 화면(테크 트리·강점·일정)에서 기회를 열면 그 자리에서 같은 모달(`OppEntity`). '어떻게 골랐나'는 추천 활동 탭 오른쪽 작은 링크(모달 안 깔때기). 신청 대상이 아니면 신청 준비는 꺼져 있다.
**신청 준비.** 에이전트가 신청 대상 확인, 일정 등록, 신청서 초안을 맡는다. 학생은 남은 일만 하고 '이대로 신청'(승인), '고쳐 줘', '안 할래'로 답한다. 남은 준비가 있으면 '이대로 신청'은 열리지 않는다. 실제 신청은 학생이 챌린지스퀘어에서 직접 한다는 한 줄을 둔다. 실제 연동은 없으니 예시 링크로 둔다. v2.1: 신청 단계 막대에 이대로 신청·고쳐 줘·안 할래 셋을 함께 두고(고쳐 줘는 초안 단계로 가서 고칠 칸을 연다), 신청 뒤 완료 화면에 '에이전트가 일정에 넣었어요 · 활동 일시' 한 줄.
**내 활동 보드.** 한 칸에 여러 상태를 묶는다(할 것: 신청 준비·결과 대기). 떨어진 신청도 경고색 없이 '끝난 것'에 둔다. 우선순위 숫자·완료 속도·경고색 없음. 끝난 활동의 '회고 쓰기'가 회고 인터뷰로 바로 열린다.
**회고 인터뷰.** 경량 LLM 이 상황별 대화 스키마(질문 순서, 끝내는 조건)로 묻는 흉내를 스크립트로 구현한다. 순서는 상황 → 역할 → 한 일 → 결과 → 배운 점 → 다음에 해 볼 것. 상황은 에이전트가 먼저 채우고 빠진 것만 묻는다. 답이 짧으면 한 번 더 묻는다. 수치는 학생이 말한 것만 적는다. 위쪽 단계 칩, 오른쪽 기록 카드에 답이 채워진다. 기록 카드에는 '학교 확인'/'직접 입력', 공개 범위(기본 나만 보기), '추천에 쓰기' 스위치.
**나의 분석.** 테크 트리: 분야마다 왼쪽 시작점에서 오른쪽으로 뻗는 가지 하나, 노드는 내용 폭의 작은 상자이고 선으로 이어진다. 왼쪽에서 오른쪽이 활동의 심화 수준(입문, 중급, 심화)이고, 단계 이름은 위 한 줄 옅은 눈금으로만 보인다(v1.9, 2026-11-04). 열 칸·분야 사이 가로선은 그리지 않고 여백으로 나눈다(v1.6, '칸으로 나뉘어 보여 별로' 피드백). 색은 내가 한 활동에만(분야색 테두리 + 아주 옅은 면, 하는 중은 겹테두리). 내가 한 가장 높은 단계보다 아래인데 한 활동이 없는 단계는 회색 실선 노드 + '건너뜀' 꼬리표이고 그 구간 선도 회색이다(누르면 이 단계에서 하는 활동과 지금 열린 기회). 회색 점선 테두리 + D-n 은 지금 할 수 있는 활동으로, 내가 한 가장 높은 단계와 그 위에만 놓는다. 시작점 '?'는 안 해 본 분야. 다른 분야로 이어진 같은 일(점선 경로)은 평소 숨기고 노드에 올리거나 누르면 그 노드의 경로만 그린다. 단계당 노드 3자리(+n 접기, 내 활동이 있는 단계는 추천 1개), 후보만 있는 줄은 2자리. 글로벌 분야색은 회색이 아닌 옅은 보라(회색은 안 한 것에만). 요약 판의 작은 그림과 기록 지도(학기 눈금 위 분야별 점, 같은 분야 기록끼리 선)도 같은 시각 언어를 쓴다. 단계 이름만 쓰고 숫자·레벨·완성률은 없다. 나만 본다. 경험 지도(v1.9): 지식 그래프. 역량은 남색 채운 큰 원(흰 글자, 옅은 남색 고리), 활동은 분야 색 작은 원(이름은 아래 낱말 단위 두 줄), 묶음은 옅은 회색 영역 + 이름표. 선은 활동→역량 근거(확인 실선, AI 추정 옅은 점선, 화살표)와 활동→활동 이어짐. 기본 화면은 묶음 단위로 접는다: 묶음 → 역량 요약 선(묶음마다 역량 셋까지, 굵기 = 근거 수, 확인 근거가 있으면 실선·추정뿐이면 점선), 활동마다의 근거 선은 묶음·역량을 고르거나 마우스를 올렸을 때만 펼친다. 관계 이름은 허브 옆 '근거 n' 한 번, 이어짐 선에만 '이어짐'. 오른쪽 칸은 묶음 목록(분야 색 점 + 이름 + 활동 수, 최대 5개). 하나를 누르면 그 묶음만 진하게(영역 옅은 초록) 하고 목록 아래에 분석을 편다. 역량을 누르면 그 근거 활동만 강조하고 칸 위에 근거 수 한 줄. 활동은 기록 서랍, 이어짐 선은 맞는지 답하는 서랍. 그래프 칸은 남은 높이를 채우고, 다 못 넣으면 그 칸 안에서만 스크롤. 요약 판 작은 그림은 왼쪽 묶음(활동 점 + 이름)에서 오른쪽 역량 허브 셋으로 곡선을 잇는다. 목업 `analysis-experience-map.png` 는 옛 격자 지도라 구성이 다르다. 관심 흐름(v2.0, 2026-11-04): 카드 머리 키워드 한 줄('26-1부터 창업·기획') + 학기 돌아보기 3단(해마다 가장 많이 한 분야, '2024년 개발로 시작 → 2025년 AI·데이터로 넓힘 → 2026년 창업·기획에 모임', 옆에 '기록 n개를 학기별로 셌어요'). 주 그림은 가로 학기 × 세로 분야, 기록 하나 = 점 하나, 학기마다 가장 많이 한 분야를 옅은 회색 곡선 하나로 잇는 '지나온 길'. 기록이 없는 학기는 옅은 칸으로만 두고 경고하지 않는다. '처음부터 보기'는 학기를 한 칸씩 채우며 지금 학기 이름과 대표 활동 하나를 보여 주고(움직임 줄이기면 바로 전체), 학기를 누르면 서랍에서 분야 비율, 대표 회고 한 줄, 그 학기 활동을 본다. 아래 한 줄 '보는 구간' 막대로 학기 범위를 고른다(이야기·셈도 그 구간 기준). 목업 `analysis-interest-flow.png` 의 오른쪽 학기 칸은 서랍으로 옮겼다. 나의 강점(v1.7): 머리 키워드 한 줄('문제해결 · 소통이 가장 자주 드러나요') + 강점별 근거 기록 점 행(기록 하나 = 점 하나, 같은 기준선, 근거 많은 순, 확인 = 채운 점, AI 추정 = 점선, 옆에 대표 근거 한 줄과 활동 이름) + '아직 근거가 적어요' 한 줄, 오른쪽에 가장 자주 드러난 강점을 살릴 기회 1~2개. 강점을 누르면 서랍에서 근거 문장(확인 전은 맞아요/아니에요), 학기·분야 점 그림, 쓸 수 있는 곳(추천 후보, 신청서에 쓸 확인된 문장, 보여 주기만)을 본다. 자기 평가 비교는 없다(2026-11-03). v1.9(2026-11-04)에서 점 행을 육각형 레이더로 바꿨다: 축 6개 = 역량 6개, 값 = 근거 기록 수(점수 아님), 동심 육각형 눈금은 2개 단위로 위 축에 한 번만 적고, 실선+옅은 네이비 채움 = 확인한 근거, 옅은 점선 윤곽 = AI 추정까지 전체, 꼭짓점마다 '역량 / 확인 n · 전체 m' 이름표(가장 확실한 강점만 이름표를 진하게). 위 전환 '지금 / 2025년 말 / 2024년 말'은 그때까지 쓴 기록의 확인 근거를 지금(가는 선)과 겹쳐 지난 나와만 비교한다. 꼭짓점을 누르면 옆 칸(대표 근거 1~2문장 + 살릴 기회)이 바뀌고 '근거 모두 보기'가 서랍을 연다. 같은 수치의 표는 화면 밖(sr-only)에 있다. 근거가 없으면 점선 육각형 + 한 줄 + 버튼 하나. 요약 판의 작은 그림도 같은 육각형. 목업 `analysis-strengths.png` 는 옛 비교 화면이라 구성이 다르다. 발견은 질문 카드('맞아요/아니에요')이고 확인한 것만 추천에 쓴다. 다른 화면에서 역량은 점 행으로 보여 주고 육각형 차트는 쓰지 않는다(나의 강점만 예외).
**기록 보관함.** 학기·분야·역량으로 거르는 한 줄, 학기 안은 카드 격자. 카드를 누르면 경험 카드 서랍(경험: 상황·역할(과제)·한 일(행동)·결과 / 돌아보기: 배운 점·다음에 해 볼 것, '면접 답변' 보기와 복사, 역량 근거, 공개 범위, '이 기록을 추천에 쓰기'). 회고 대기 띠는 활동 이름마다 바로 회고를 연다(Day One). 보관함에서 2~5개를 골라 '경험 카드 묶음'(`#/activities/records/portfolio`)으로 한 화면에 모아 인쇄·전체 복사한다(대리 제출 없음). 점검: `docs/qa/records-ref-2026-11-04.md`.
**도전 과제.** 레벨·점수·순위 없음. 숨은 과제는 달성하기 전에는 목록에 없다(희귀도·힌트·전시 없음). 진행도 막대(2 / 3). 달성하면 무엇을 잘했는지 한 줄. 예시 과제는 `concept.md` 의 표를 쓴다.
**나의 분석 요약(v2.1, 2026-11-04).** 덩어리 둘: 2×2 그림 판(칸 머리말은 하위 화면 머리 키워드와 같은 말, 나의 강점은 '문제해결 · 확인 근거 10개', 빈칸은 점선 육각형)과 확인할 발견 카드. 카드 머리는 '확인할 것 n개'(다 하면 '모두 확인했어요'). 카드: 질문(text-lg) → 셈 한 줄 + 근거 기록이 발견 하나로 모이는 도식(함께 하나의 버튼, 근거 서랍) → 상태 점 + 추천에 쓰이는 곳 한 줄 → 맞아요·아니에요(보조 두 칸) + 잘 모르겠어요(옅은 버튼, 확인 전일 때만) → 카드 밖 '발견 n개 모두 보기'. 확인 전은 점선 테두리, 답한 것은 실선. 빈 상태는 회고 셋이 발견으로 모이는 점선 틀 + 한 줄 + 버튼 하나.

**친구.** 프로필은 기본 비공개. 비공개면 친구 찾기·팀원 모집·명예의 전당을 못 쓴다(잠금 안내가 아니라 '공개하면 열려요' 한 화면). 공개 범위(설정 → 공개 범위)는 공개하면 열리는 기능과 보이는 것을 한 화면에. 회고는 고른 것만. 발견·역량 근거는 항상 나만. 민감한 활동은 기본으로 빠진다. 팀원 모집은 대회·해커톤·공모전에 글을 올리고 같은 기회에 관심 표시한 공개 학생에게 먼저 보인다. 명예의 전당은 순위·점수 대신 선정 이유와 거쳐 온 활동을 보여 주고 내 기록과 나란히 비교하지 않는다. 선정 기준·운영 주체는 미정이라 '검토 중' 표시를 둔다. 선배 경로(명예의 전당 카드, '이 활동을 해 본 친구·선배'의 선배 이름)는 같은 서랍 모양: 줄은 시간, 칸은 입문·중급·심화(테크 트리와 같은 `levelOf` 규칙). 경로를 공개하지 않은 선배는 이름만 점선으로 보이고 열리지 않는다.

## 5. 아직 정하지 않은 것 (정한 척 구현하지 않는다)

추천 후보 개수(지금은 가장 추천 1 + 대안 최대 9), 기회 종류(카테고리) 체계, 역량 체계(목업의 5대 역량은 예시), 보드 상태 이름, 테크 트리 분야·심화 수준 기준, 회고 알림 시점·횟수, 명예의 전당 선정 기준. 화면에서는 예시 값으로 두고 '예시'임을 프로토타입 정보에서 밝힌다.

## 6. 만들지 않는 것

점수·레벨·XP·순위표, 교과 학습 지원(코스 에이전트 몫), 대리 신청, 실제 AI·학교 API·챌린지스퀘어 연동, 로그인.

## 7. 높이 단계 · 스크롤바 · 패널 (v1.4, `docs/design/ia-navigation.md` 9절)

기준 크기는 노트북 배율인 **1280×640, 1366×650, 1536×730** 과 1440×900 이다. 모든 경로에서 `document.scrollHeight ≤ innerHeight`(페이지 스크롤 0)여야 한다.

- **틀 높이**: `html`·`body` 는 스크롤하지 않고, `.app` 이 `100dvh` 를 정확히 채운다. 사이드바와 본문 칸(`.app-main`, `data-scroll-root`)이 각자 높이를 갖는다. 화면 틀 `.os` 는 본문 칸의 남은 높이를 채운다. 내용이 넘치면 페이지가 아니라 **본문 칸만** 스크롤한다(최후 수단). 창 높이가 `--app-min-h`(600px)보다 낮으면 숨기거나 자르지 않고 본문 칸이 스크롤한다.
- **스크롤 위치**: 맨 위로 보내기나 스크롤 되살리기는 `window` 대신 `setPageScrollTop` / `pageScrollTop` / `onPageScroll`(`src/components`)을 쓴다.
- **높이별 밀도 한 단계**(`@media (max-height: 759px)`, `tokens.css`): `--main-pad-t/x/b`, `--card-pad`, `--card-head-gap`, 머리 높이 `--os-head-h` 44→36, 간격 `--os-gap` 16→12, 큰 글자 `--fs-page`·`--fs-lead`·`--fs-title` 한 단계(화면 제목 24→20), 메뉴 줄 `--nav-item-h` 38→36. 본문 15px 이하 글자와 32px 클릭 대상은 줄이지 않는다. 사이드바 간격을 줄이고, 학생 카드는 이름 한 줄만 남긴다. 화면 CSS 는 카드 여백에 값을 박지 말고 `--card-pad` 를 쓴다. 낮은 높이에서 빼도 되는 보조 줄은 `.only-tall` 로 둔다(꼭 필요한 정보에는 쓰지 않는다).
- **스크롤바**: 전역 한 가지 모양. 6px(`--scrollbar-size`), 트랙 투명, 썸은 옅은 회색(`--scrollbar-thumb`)이고 칸에 마우스를 올리거나 스크롤하는 동안만 진하게(`--scrollbar-thumb-active`, 스크롤 중에는 `data-scrolling` 이 붙는다: `src/app/scrolling.ts`). 화살표 버튼 없음. Firefox 는 `scrollbar-width: thin` + `scrollbar-color`.
- **더 있음 그림자** `.os-scroll`: 칸 안 스크롤 + 위·아래 가장자리 옅은 그림자(`--scroll-shade`). 끝에 닿으면 그 쪽 그림자가 사라진다. 흰 카드가 아닌 바탕 위에서는 `.os-scroll--page`(또는 `--os-cover` 를 바탕색으로).
- **패널 레이아웃** `<Panel title eyebrow action footer note>`(또는 클래스 `ui-panel` / `ui-panel__head` / `ui-panel__body` / `ui-panel__foot`): 머리 / 내용(칸 안 스크롤) / 행동 막대. 행동 막대는 내용과 같은 흐름에 있어 내용을 덮지 않는다. 부모가 높이를 정해 줘야 내용 칸이 스크롤한다(`.os__body--fill` 칸, 그리드 칸). 고정 행동 막대에는 `data-action-bar` 를 붙여 겹침 측정에 잡히게 한다.
- **단계 표시** `<Stepper label steps current onStep>`: ① 고르기 › ② 자세히 › ③ 준비 › ④ 신청 처럼 흐름을 나눌 때 머리에 한 줄. 지금 단계만 진하고, 지난 단계는 체크로 바뀌어 누르면 돌아간다(다음 단계로 건너뛰지 않는다). 한 화면에서 한 가지 결정만 한다.
- **'자세히' 진입 규칙** `openEntity(ref, { as })`: 기본(`drawer`)은 같은 화면 위 오른쪽 서랍, 닫으면 제자리. 훑어보고 고르는 곳(목록·보드·그림 조각)에서 쓴다. `{ as: 'page' }` 는 그 항목의 상세 경로로 옮기고 빵부스러기 한 줄로 돌아온다. 그 안에서 할 일이 이어지는 곳에서 쓴다. 상세를 같은 화면 오른쪽 칸 교체로 만들지 않는다.
- **측정**: `public/qa-frame.html?w=1280&h=640&s=0.6&path=%23%2Frecommend`(h 는 iframe 높이, s 는 좁은 창에서 한 장에 담는 축소 배율). 숫자는 DOM 실측(`document.documentElement.scrollHeight`, 본문 칸 `scrollHeight - clientHeight`, 행동 막대와 내용 사각형 교차)으로 댄다.

## 8. 레이아웃 검사 (v1.5, 2026-11-03)

화면을 눈으로만 보면 예시 학생·넉넉한 크기에서만 보게 된다. 그래서 기계로 먼저 거른다.

- `npm run audit:layout`(`scripts/audit-layout/`): 빌드 결과를 띄워 **라우트 표(`router.ts` KNOWN_SUBS)의 모든 경로 × 7개 크기 × 학생 상태 4개**(새 학생 '멘토링', 새 학생 '아직 모르겠어요', 예시, 가입 인터뷰 단계)를 돌고 신청 준비 단계(초안·신청)까지 누른다. CI 에서도 돈다.
- 크기: 1280×640, 1366×650, 1440×700, 1536×730, 1440×900, 1920×960, 1024×640(깨지지 않음만).
- 걸리는 것: 페이지·본문 칸 스크롤, 가로 넘침, 카드 밖으로 삐져나옴, 잘림(HTML·SVG), 버튼·글자 겹침, 창 밖 버튼, 늘어난 빈 칸, 작은 글자, 차트 이름표 중복, 로딩 뼈대 같은 빈 상태, 오른쪽이 빈 화면, 콘솔 에러. 말줄임은 경고.
- 일시 오류 처리(v2.2): 탐색·로드 단계의 일시 오류(page.goto 시간 초과, ERR_CONNECTION_RESET 등)는 그 화면만 최대 2번 다시 시도하고, 그래도 실패하면 '검사 실행 오류'로 실패한다. 레이아웃 판정(넘침·겹침 등)은 다시 시도하지 않는다. 포트가 쓰이고 있으면 빈 포트를 찾아 띄우고, 서버가 응답할 때까지 기다린다. 결과 표(report.md)에 다시 시도한 횟수가 나온다. 로직은 `scripts/audit-layout/retry.mjs`(단위 테스트 `retry.test.mjs`).
- 의도된 예외 표시: `data-fill`(남은 높이를 채우는 칸), `data-allow-overlap`(차트 마커 위 이름표), `data-allow-repeat`(줄마다 같은 이름이 나오는 차트), `data-audit-skip`(개발용 칸). 쓰면 이유를 주석으로.
