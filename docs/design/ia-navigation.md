# 화면 깊이와 이동 동선 (v1.0)

> 2026-11-03 사용자 피드백으로 v0.9 를 고친다.
> 1. "이런 중복 진입점 다 없애." (예: 나의 분석 상세에 빵부스러기 + 뒤로 버튼 + 탭이 모두 같은 곳을 가리킴)
> 2. "도전 과제는 스팀처럼 프로필 화면에 친구 도전 과제 이런 거 뜨게 하고 메인 메뉴에서는 없애."
> 3. "메인 메뉴에서 하위 항목으로 들어갈 수 있는 것은 하위 항목으로. 메인 메뉴에는 핵심만."
> 4. "요약을 하라고 했는데 왜 아이콘으로 바꿨어. 핵심 내용만 사용자에 맞는 내용으로 띄워야지."
> 근거 자료: docs/product/layout-reference.md, docs/product/concept.md. v0.9 의 '그림이 주인공' 원칙은 4번으로 바뀌었다: **요약은 그림이 아니라 그 학생에게 맞는 핵심 문장과 값**이고, 그림은 그 문장을 돕는 작은 보조다.

## 1. 메뉴 트리 (사이드바가 유일한 이동 수단)

```
홈                    #/home
추천 (새 후보 배지)     #/recommend
내 활동               #/activities          (요약)
  ├ 일정              #/activities/schedule (타임라인·보드·목록 보기 전환)
  └ 기록              #/activities/records  (기록 지도·보관함, 회고 쓰기는 여기서)
나의 분석              #/analysis            (요약)
  ├ 테크 트리          #/analysis/techtree
  ├ 경험 지도          #/analysis/map
  ├ 관심 흐름          #/analysis/flow
  └ 나의 강점          #/analysis/strengths

왼쪽 아래 (메뉴 밖)
학생 카드 → 프로필     #/profile             (스팀식 프로필: 나, 도전 과제, 친구 소식)
  ├ 친구              #/profile/friends     (프로필 요약의 카드로만 간다)
  ├ 팀원 모집          #/profile/recruit     (〃)
  └ 명예의 전당        #/profile/hall        (〃)
(톱니바퀴) 설정         #/settings/...        (학생 카드 옆)
```

- 메인 메뉴는 4개(홈, 추천, 내 활동, 나의 분석). 프로필은 메뉴가 아니라 사이드바 왼쪽 아래 학생 카드(아바타 + 학과·학년) 전체가 링크다(`aria-label="내 프로필"`). 프로필 화면과 그 하위에 있으면 카드가 활성(`aria-current`)이다. 1024 아이콘 폭에서는 아바타만 남고 누르면 프로필로 간다.
- '기록', '도전 과제', '친구'는 메인 메뉴에서 빠지고 하위로 들어간다.
- 하위 항목은 사이드바에서 부모 아래 들여 쓴다. 지금 보고 있는 부모만 펼치고 나머지는 접는다(부모를 누르면 요약 화면으로 가고 펼쳐진다). 지금 위치는 하위 항목의 활성 표시로 보인다.
- 사이드바 메뉴에 없는 화면은 여섯이다: 신청 준비 #/recommend/prepare/<id>, 회고 인터뷰 #/activities/records/interview/<id>, 경험 카드 묶음 #/activities/records/portfolio, 친구 프로필 서랍, 그리고 프로필 하위 친구·팀원 모집·명예의 전당. 프로필 하위는 흐름 화면처럼 머리에 빵부스러기 '프로필 › 친구' 한 줄로 부모로 돌아간다.
- 옛 경로(#/records/*, #/challenges/*, #/friends/*, #/recommend/list, #/recommend/compare, #/activities/board|list)는 새 경로로 넘긴다.

## 2. 진입점은 하나 (중복 금지 규칙)

1. **이동은 사이드바가 맡는다.** 화면 안에 사이드바 항목을 다시 부르는 탭, 버튼, 링크, 머리 행동을 두지 않는다. 하위 화면 안의 탭(테크 트리/경험 지도/…)은 없앤다.
2. **위치 표시는 하나.** 사이드바에 있는 하위 화면은 제목만 둔다(빵부스러기·뒤로 버튼 없음, 사이드바가 위치를 보여 준다). 흐름 화면(신청 준비, 회고 인터뷰)과 프로필 하위(친구·팀원 모집·명예의 전당)만 빵부스러기 한 줄로 부모로 돌아간다. 뒤로 버튼은 쓰지 않는다(브라우저 뒤로 가기는 그대로 된다).
3. **한 화면 안에서 같은 목적지로 가는 길은 하나.** 머리 버튼 + 카드 링크 + 띠처럼 같은 곳을 두 번 이상 부르지 않는다. 남길 하나는 내용이 붙은 쪽(요약 카드, 할 일 항목)이다.
4. **요약 카드는 이동이 아니라 내용이다.** 요약 화면의 카드는 그 학생의 핵심 문장과 값을 보여 주고, 누르면 그 하위 화면으로 간다(사이드바와 같은 목적지지만 '내용을 펼치는' 행동이라 허용). 대신 같은 화면에 그 하위 화면으로 가는 다른 버튼은 두지 않는다.
5. **보기 전환은 이동이 아니다.** 일정 화면의 타임라인/보드/목록처럼 같은 데이터를 다르게 보는 전환은 화면 안 한 곳(세그먼트)에만 둔다.
6. 같은 대상(기회·활동·기록·사람)은 어디서 눌러도 같은 서랍(openEntity)이 열린다.

## 3. 요약 화면이 보여 줄 것 (그 학생에게 맞는 핵심만)

요약 = **한 줄 문장 + 값**. 문장은 학생의 실제 상태에서 계산한다("기록 5개 중 3개가 창업·기획이에요"). 그림은 문장 옆 작은 보조(막대·점 몇 개)로만. 아이콘·장식만 있는 타일, 숫자만 있는 카드, 일반 설명 문장은 쓰지 않는다. 데이터가 없으면 그 학생이 다음에 할 일 한 줄.

| 화면 | 보여 줄 요약 (예시는 지금 예시 데이터 기준) |
| --- | --- |
| 홈 | ① 오늘 할 일 최대 3개(회고 대기, 마감 임박 준비, 오늘 있는 활동: "SW 튜터 모집 사전 설문 오늘 18:00 마감") ② 가장 추천 1개 + 이유 한 줄 ③ 이번 학기 한 줄("이번 학기 활동 4개, 창업·기획을 가장 많이 했어요") ④ 곧 있어요 14일 타임라인(보조). 나의 흐름 고리·메뉴 바로가기는 없앤다(사이드바와 중복). 에이전트에게 묻기는 유지 |
| 추천 | 가장 추천 1개(이유 문장, 마감·기간·방식) + 그 아래 나머지 후보 목록-상세를 한 화면에. '후보 모두 보기', '비교해서 고르기', '다른 대안' 버튼을 하나로 합친다(목록 자체가 대안). 비교 표는 목록의 보기 전환. 고른 방법 깔때기는 문장("후보 10개 중 마감·대상·시간을 맞춘 7개예요")으로 줄이고 그림은 서랍으로 |
| 내 활동(요약) | "할 것 3개 중 2개가 이번 주 마감이에요", 다음 마감 2개(제목·D-n), 회고 대기 n개(누르면 회고 인터뷰), 진행 중 활동 이름. 카드: 일정 요약 → 일정, 기록 요약("기록 6개, 이번 학기 3개") → 기록 |
| 나의 분석(요약) | 하위 넷 각각 한 줄 통찰: 테크 트리 "창업·기획 심화까지 · 글로벌은 중급을 건너뜀", 경험 지도 "'듣고 정리하기'가 기록 3개에 이어져요", 관심 흐름 "26-1부터 창업·기획이 계속 가장 많아요", 나의 강점 "문제해결: 근거 4개". 확인할 발견은 질문 카드로 이 화면에서 바로 답한다(맞아요/아니에요) |
| 프로필 | 스팀 프로필처럼: 머리(이름 대신 '나', 학과·학년, 공개 상태) → 전시한 도전 과제 → 도전 과제 진행("달성 2개, '세 갈래 길'까지 1곳 남았어요" + 다음 과제 2~3개 진행 막대, 숨은 과제는 '?') → 최근 활동 → 친구 소식("다온 님이 '첫 회고'를 달성했어요", 친구 프로필 서랍에서 그 친구의 전시 도전 과제와 한 활동). 비공개여도 내 도전 과제는 보인다. 친구·모집·전당 영역만 잠기고 '설정에서 공개하기' 한 곳. 도전 과제 전체 목록은 프로필 안 '도전 과제' 영역의 펼치기로(별도 메뉴 없음) |

지킬 것(기준 문서): 레벨·XP·점수·순위·완료율·퍼센트 희귀도 없음, 다른 학생과 비교 없음, 발견·역량 근거는 공개 안 함, 숨은 과제는 조건 없이 희귀도만.

## 4. 측정 기준

- 모든 화면에서 같은 목적지로 가는 진입점(링크·버튼·탭) 수 ≤ 1 (사이드바 제외). DOM 에서 href/라우트 대상별로 세어 보고한다.
- 사이드바 메인 항목 4개, 하위 항목 6개. 프로필은 왼쪽 아래 학생 카드.
- 요약 화면(홈, 내 활동, 나의 분석, 프로필)의 각 카드에 학생 데이터에서 계산한 문장이 1개 이상. 아이콘만 있는 타일 0.
- 요약 화면 첫 화면 본문 300자 이하는 유지.

## 5. 이전 설계(v0.9)에서 바뀐 것

- 도전 과제·친구·기록 메뉴 삭제(하위로 이동). 친구 L1 의 세 갈래 그림, 분석 L1 의 축소판 타일, 도전 과제 배지 벽 L1 은 요약 문장 카드로 바뀐다.
- L2 의 뒤로 버튼과 하위 탭 삭제. 빵부스러기는 흐름 화면에만.
- 홈의 나의 흐름 고리, 추천의 '후보 모두 보기'·'비교해서 고르기' 버튼, 내 활동의 '보드로 보기'·'목록으로 보기', 기록의 '보관함 보기' 같은 중복 버튼 삭제.


## 6. v1.1 수정 (2026-11-03 사용자 피드백)

> "글로 때우지 말고 다이어그램이랑 이미지 위주로 하라고, 보기 쉽게." / "추천 페이지도 스크롤 때문에 정보가 한눈에 안 들어옴."

v1.0 3절의 '요약 = 한 줄 문장 + 값, 그림은 보조'를 이렇게 바꾼다.

1. **요약의 주인공은 그 학생의 데이터를 그린 그림이다.** 장식용 축소판이 아니라, 읽으면 바로 뜻이 들어오는 차트·도식이어야 한다. 축·점·막대에 **직접 라벨**(분야 이름, 값, 날짜)을 붙여 범례를 찾지 않아도 읽힌다.
2. **글은 키워드 한 줄만.** 문장 대신 15자 안팎의 머리말(예: '창업·기획 집중 · 개발 미경험', '이번 주 마감 2'). 문단·설명 문장·같은 말 반복 금지.
3. 아이콘만 있는 타일, 뜻 없는 점 무늬는 여전히 금지. 그림의 모든 표시는 실제 데이터다.
4. **첫 화면은 1440×900 에서 페이지 스크롤 없이 한 화면.** 목록이 길면 그 목록 칸 안에서만 스크롤한다. 1280×800 에서도 핵심(가장 추천, 오늘 할 일, 각 요약 그림)은 첫 화면에 보인다.
5. 측정: 각 첫 화면(홈, 추천, 내 활동, 일정, 기록, 나의 분석, 프로필) document.scrollHeight ≤ 뷰포트 높이(1440×900). 요약 카드의 문장 글자 수(라벨 제외) 카드당 20자 이하.

### 6-1. 스크롤과 화면 일체성 (전체 화면에 적용)

> "전체적으로 스크롤 때문에 정신없음. 스크롤은 진짜 필요할 때만 쓰고 웬만하면 화면 일체성, 사용의 일관성 지키게 해."

1. **페이지 스크롤 금지가 기본이다.** 모든 화면(요약, 하위 화면, 흐름 화면, 설정)은 1440×900 에서 한 화면에 들어온다. 페이지 전체가 스크롤되는 화면을 만들지 않는다.
2. **스크롤은 칸 안에서만, 정말 필요할 때만.** 끝이 정해지지 않은 목록(후보, 기록, 대화, 도전 과제 전체 목록)만 자기 칸 안에서 스크롤한다. 칸에는 위아래 경계(옅은 그림자나 선)로 더 있다는 걸 보여 준다. 한 화면에 스크롤 칸은 하나까지.
3. **같은 틀.** 모든 화면은 같은 구조다: 위쪽 머리(제목·핵심 한 줄·보기 전환, 높이 고정) → 아래쪽 본문이 남은 높이를 채운다. 본문 배치는 화면 종류별로 같다: 요약 = 카드 격자, 목록 화면 = 왼쪽 목록 칸 + 오른쪽 상세 칸, 흐름 화면 = 왼쪽 진행 + 오른쪽 결과. 같은 종류의 화면은 같은 칸 비율·같은 간격을 쓴다.
4. **넘칠 것 같으면 줄인다.** 내용이 한 화면을 넘으면 스크롤을 붙이기 전에 먼저 (a) 덜 중요한 것을 서랍으로 보내고 (b) 그림을 작게 하고 (c) 목록을 칸 안 스크롤로 바꾼다.
5. 측정: 모든 경로에서 1440×900 document.scrollHeight ≤ 900, 1280×800 ≤ 800(안 되면 이유를 보고). 화면마다 스크롤 칸 수 ≤ 1.

## 7. v1.2 사용성 감사 반영 (2026-11-03)

1. **새 학생과 예시.** 가입 인터뷰를 마치면 새 학생(활동·기록·도전 과제 달성·친구 0, 기회만 있음)으로 시작한다. '예시로 둘러보기'만 예시 학생 데이터를 채운다. 설정 › 프로토타입 정보의 '보는 데이터'에서 둘을 바꾼다(새 학생이 쓴 것이 있으면 한 번 묻는다). 상태는 `AppState.demo`.
2. **첫 사용 상태 = 그림 틀 + 다음 행동 한 줄.** 데이터가 없는 칸은 같은 자리에 축·칸만 옅게 그린 틀(`GhostPic`)과 다음 행동 한 줄을 둔다. 값처럼 보이는 표시와 점선(AI 추정 표시)은 쓰지 않는다.
3. **분야 이름은 분야 묶음 하나.** 학생에게 보이는 곳(가입·설정 선택지, 태그, 추천 이유, 비교표)은 개발·AI·데이터·창업·기획·멘토링·글로벌·기타만 쓴다. 세부 분야는 추천 규칙 안에서만 쓴다(`fieldName`).
4. **홈은 같은 일을 두 번 보이지 않는다.** 오늘 할 일 = 오늘·내일, 곧 있어요 = 모레부터 14일. 타임라인 점에는 이름을 바로 붙인다(`Timeline labels`).
5. **메뉴 이름 = 화면 제목.** 홈 화면 제목은 '홈', 학생 카드(내 프로필)로 여는 화면 제목은 '내 프로필'.
6. **한 화면 틀은 `src/styles/screen.css` 하나.** `.os`(머리 고정) → `.os__body`(카드는 위에서부터 내용 높이, 남은 높이를 넘을 때만 줄어 칸 안 스크롤) / `.os__body--fill`(목록-상세·흐름 화면처럼 칸이 남은 높이를 다 씀) / `.os-scroll` / `.os-card`. 칸 간격 `--os-gap`, 머리 높이 `--os-head-h`, 카드 여백은 이 틀이 정한다. 카드를 화면 높이에 맞춰 늘려 빈칸을 만들지 않는다.
7. **신청 준비.** '고쳐 줘'는 방향 칩(더 짧게·더 구체적으로·다른 경험 쓰기)과 한 줄 요청을 받고 실행 기록에 '초안을 고쳤어요'를 남긴다. 학교 로그인이 필요한 항목은 '설문 열기'(새 탭)로 연 뒤 '했어요'로 체크한다. '이대로 신청' 뒤에는 체크리스트 자리가 완료 그림으로 바뀌고 갈 곳은 '일정에서 보기' 하나다.

## 8. v1.3 사용성 감사 2차 (2026-11-03)

1. **같은 말은 한 번.** '여기 있는 분석은 나에게만 보여요'는 나의 분석 요약 머리에만 두고, 하위 화면은 눈 아이콘(`aria-label="나에게만 보여요"`)만 둔다.
2. **관심 흐름 기본 구간 = 첫 기록 학기부터.** 구간 밖 학기는 그리지 않고, 시작 학기 슬라이더로 넓힌다(`defaultRange`). 첫 기록 뒤의 빈 학기는 경고 없이 그대로 둔다.
3. **모르는 하위 경로는 주소를 바꾼다.** `#/settings/notify` → `#/settings/profile`, `#/analysis/x` → `#/analysis`. 그 메뉴 안에서 아는 가장 긴 앞부분, 없으면 메뉴의 기본 경로로 replace 한다(`canonicalPath`).
4. **빈 상태 버튼은 지금 할 수 있는 일로.** 기록이 없어 빈 칸의 버튼은 `nextStep(activities)`가 정한다: 끝난 활동이 있으면 '회고 쓰러 가기', 하는 활동만 있으면 '일정 보기', 아무것도 없으면 '추천에서 활동 고르기'. 첫 사용 빈 상태는 `EmptyState pic={<GhostPic …/>}` 로 그림 틀 + 한 줄 + 버튼 하나. 요약 카드 안의 그림 틀은 카드 자체가 링크라 버튼을 따로 두지 않는다.
5. **칸 안 스크롤의 포커스 링은 안쪽으로**(`--focus-ring-inset`). 바깥 링은 스크롤 칸 가장자리에서 잘린다.
6. 진입점 점검(`npm run audit:entries`)은 새 학생 상태 경로도 센다.


## 9. v1.4 정보량 조절·단계 나누기 (2026-11-03 사용자 피드백)

> "아직도 한 페이지의 정보 밀집도가 많아. 단계를 나누고, 한 페이지에 정보의 로드를 조절해. 누르면 상세 정보를 볼 수 있는 구조로 뎁스를 나눠. 전체 화면이 스크롤되는 오류 있어. 스크롤바가 올드해 보이니 깔끔하게."
> 사용자 화면 캡처: 추천 화면에서 '왜 추천했나' 상자가 아래 행동 버튼 뒤로 잘리고, 목록 칸에 오래된 회색 스크롤바가 보인다. 사용자 브라우저 높이는 800보다 낮다(노트북 배율).

1. **기준 화면 크기를 실제 노트북으로 낮춘다.** 1280×640(1920×1080 화면 150% 배율 + 브라우저 막대)과 1366×650, 1536×730 에서 페이지 전체 스크롤 0, 잘림·겹침 0. 높이가 더 작으면(600 미만) 숨기거나 잘라 내지 말고 본문 칸만 스크롤.
2. **한 화면의 정보량 상한.** 첫 화면에 주요 덩어리(카드·패널) 최대 3개, 한 덩어리 안 데이터 항목 최대 5개, 버튼은 주 행동 1개 + 보조 2개까지. 넘는 것은 다음 단계로 보낸다.
3. **단계를 나눈다.** 한 화면에서 한 가지 결정만 하게 한다. 예) 추천: ① 후보 고르기(목록 + 핵심 3가지만) → ② 자세히 보기(누르면 상세 화면/서랍: 사실 4칸, 추천 이유 도식, 근거) → ③ 신청 준비(체크리스트) → ④ 승인. 회고: 단계 칩이 이미 있으니 한 번에 한 질문. 설정: 한 칸에 한 주제.
4. **뎁스: 요약 → 상세.** 첫 화면은 고르는 데 필요한 것만(제목, 분야, 마감 같은 2~3개). 이유·근거·사실 표·원문 링크·실행 기록은 누른 뒤에 보인다. 상세는 같은 화면 오른쪽 칸 교체가 아니라 '자세히' 단계(하위 경로 또는 서랍)로, 돌아오는 길은 빵부스러기 한 줄 또는 서랍 닫기.
5. **스크롤바**: 브라우저 기본 회색 스크롤바를 쓰지 않는다. 얇고(6px 안팎) 옅은 색, 칸에 마우스를 올리거나 스크롤할 때만 진하게, 트랙은 투명. 모든 칸 안 스크롤에 같은 모양.
6. **잘림 금지 재확인**: 고정된 행동 막대가 내용을 덮으면 안 된다. 내용과 행동 막대는 같은 흐름 안에 두거나, 내용 칸이 행동 막대 높이만큼 비켜야 한다.
7. 측정: 위 3개 크기 + 1440×900 에서 모든 경로 document.scrollHeight ≤ innerHeight, 겹침(행동 막대와 내용 사각형 교차) 0, 화면당 덩어리 수 ≤ 3. 결과 표로 보고.
