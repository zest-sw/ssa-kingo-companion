# Research: 소프트웨어학과 공지 수집·분류 (Phase 0)

**Feature**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md) · **Date**: 2026-11-07

근거 표본: 게시판 제목 294건(2026-04-01~11-06), 본문 49건(같은 기간, 게시판 분류별 추출), 오래된 목록 2장(앞에서 401~700번째, 2025-04~09). 표본 원문은 세션 임시 폴더에만 있고 저장소에는 없다.

## R1. 실행 환경: Node 22.18 이상의 기본 TypeScript 실행

- **Decision**: `node etl/notices/run.ts`처럼 `.ts` 파일을 Node로 바로 돌린다(타입 지우기). 지켜야 할 것:
  - 타입만 가져올 때는 반드시 `import type`을 쓴다. 로컬 Node 26.4에서 확인했다: `import { Category } from '…/types.ts'`는 실행할 때 `SyntaxError: … does not provide an export named 'Category'`로 멈추고, `import type`은 통과한다.
  - 상대 경로 import에는 `.ts` 확장자를 붙인다. `tsconfig.json`의 `allowImportingTsExtensions`가 이미 켜져 있다.
  - 지울 수 없는 문법(enum, namespace, 생성자 매개변수 속성)은 쓰지 않는다.
  - 저장소 `package.json`이 `"type": "module"`이라 `.ts` 파일은 ESM으로 돈다.
- **Rationale**: 새 의존성이 없다. 팀 `.nvmrc`가 `22`라 nvm은 22.x 최신(≥22.18)을 설치한다.
- **Alternatives considered**: tsx·ts-node(새 의존성), vite-node(설치 안 됨), tsc로 JS 빌드(저장소 설정이 `noEmit`이라 빌드 단계를 더해야 함), 순수 `.mjs`(공용 `Category` 타입을 같이 못 씀).
- **Note**: `package.json`의 `engines`(`^20.19.0 || >=22.12.0`)는 팀 파일이라 그대로 둔다. ETL만 22.18 이상이 필요하고, quickstart에서 `node -v`로 확인한다.

## R2. 타입 검사와 테스트 편입

- **Decision**: `tsconfig.json`의 `include`에 `etl`을 더한다. vitest는 설정 파일이 없어 기본 include로 `etl/**/*.test.ts`를 찾는다(`vite.config.ts`에 `test` 설정 없음, `vitest.config.*` 없음). 테스트는 node 환경에서 돌고 jsdom을 직접 가져온다.
- **Constraints found**:
  - `lib`가 `ES2020`이다. ES2021 이후 API(`String.prototype.replaceAll`, `Array.prototype.at`, `findLast`, `Object.hasOwn`)를 쓰면 `tsc`가 실패한다. `replace(/…/g)`, 인덱스 접근으로 쓴다.
  - `fetch`, `AbortSignal.timeout`, `TextDecoder`는 DOM lib와 `@types/node`로 타입이 잡힌다. 런타임에서도 있음을 확인했다.
  - vitest의 변환은 쓰지 않는 import를 지워 버린다. 그래서 위의 `import type` 실수는 테스트로 잡히지 않는다. quickstart의 실제 실행이 마지막 확인이다.
- **Alternatives considered**: etl 전용 tsconfig(설정이 하나 더 생김), 타입 검사 제외(strict 규칙 위반).

## R3. HTML 읽기: jsdom(이미 설치됨)

- **Decision**:
  - 목록: `dl.board-list-content-wrap` 하나가 한 줄이다. 분류는 `.c-board-list-category`(대괄호 제거), 제목과 글 번호는 링크(`?mode=view&articleNo=N`)에서 읽는다. 정보 `li`는 첫째가 `공지`(고정글)나 `No.N`, 둘째가 작성자, 셋째가 게시일(`YYYY-MM-DD`)이다.
  - 본문: `div.fr-view` 아래만 읽는다. jsdom에는 `innerText`가 없어 노드를 직접 훑는다. 블록 요소(p, div, br, li, tr, h1~h6, table, ul, ol, pre)에서 줄을 바꾸고, td·th 앞에는 빈칸을 넣는다. 글자 속 소스 줄바꿈은 브라우저처럼 빈칸으로 읽고, `<pre>` 안에서만 줄로 본다(본문 전체가 pre인 글이 표본 301건 중 2건). 공백·nbsp를 줄이고 빈 줄을 버린다.
  - 쪽마다 창(window)을 만들지 않고 `JSDOM.fragment`로 읽는다. 보관한 301건을 읽는 최대 메모리가 1.01GB에서 370MB로 줄었다(코드 리뷰 지적).
- **Rationale**: `textContent`는 줄바꿈을 잃는다. '신청 줄' 규칙에는 줄 단위가 필요하다. 1차 표본 때 정규식으로 본문을 자르다가 이전글·다음글 제목(다른 글의 마감)까지 가져왔다. 그래서 실제 DOM 경계가 필요하다. 같은 경계 규칙을 표준 라이브러리 파서로 49건에 돌렸고, 49건 모두 본문 영역을 찾았다.
- **Alternatives considered**: 정규식(경계 오류를 실제로 겪음), cheerio·node-html-parser(새 의존성).

## R4. 수집 방식과 서버 예의

- **Decision**:
  - 목록 `https://cse.skku.edu/cse/notice.do?mode=list&articleLimit=100&article.offset=N`, 본문 `…?mode=view&articleNo=N`. 페이지는 UTF-8이다. 응답이 2xx가 아니면 실패로 본다.
  - 요청은 하나씩 보내고 요청 사이에 1초를 쉰다(`node:timers/promises`의 `setTimeout`). 요청마다 `AbortSignal.timeout(15000)`. User-Agent는 `ssa-kingo-companion-etl (+https://github.com/zest-sw/ssa-kingo-companion)`이고 이메일 같은 개인정보는 넣지 않는다.
  - 목록은 최신순이다. 고정글이 아닌 줄 가운데 기준일보다 오래된 줄이 처음 나오면 멈춘다. 고정글은 페이지마다 다시 나오므로 글 번호로 한 번만 다룬다. 다음 쪽 offset은 이번 쪽에서 읽은 일반 글 수만큼 늘린다(서버가 100건보다 적게 줘도 빠뜨리지 않게). 어느 쪽이든 글이 하나도 없으면 점검 페이지 같은 것으로 보고 멈춘다(반쪽 목록으로 결과를 바꾸지 않게).
  - 보관: 본문 영역을 찾은 페이지만 `etl/.cache/cse/<글번호>.html`에 원문 그대로 쓴다. `.tmp`에 다 쓴 뒤 이름을 바꿔 반쪽 파일을 본문으로 믿지 않게 한다. 만료는 없다(ponytail: 고쳐진 마감을 못 따라감, 필요해지면 최근 2주 글만 다시 받기).
- **Rationale**: robots.txt가 수집을 막지 않고, 1초 간격이면 부담이 작다. 원문을 그대로 두면 규칙을 고친 뒤 서버에 다시 묻지 않고 다시 판정할 수 있다.
- **Measured**: 표본 기간 7개월에 294건(월 약 43건)이라 90일이면 약 130건, 첫 실행 약 2.5분이다. 2025년 2학기 글은 목록 앞에서 약 400~550번째에 있다.
- **Alternatives considered**: 병렬 요청(서버 부담), 추출한 글자만 보관(규칙을 바꾸면 다시 받아야 함), 조건부 요청(서버 지원을 모르고 지금은 필요 없음).

## R6. 날짜 읽기

- **Decision**: 규칙 순서가 정해진 정규식 토큰 읽기. 앞에서부터 가장 구체적인 꼴을 먼저 맞춘다.
  1. `YYYY년 M월 D일`
  2. `YYYY. M. D.`, `YYYY.M.D`, `YYYY/M/D`, `YYYY-MM-DD`
  3. `'YY.M/D`, `'YY.M.D`(앞 따옴표 두 자리 연도)
  4. 영어 `Mon[th] D(st|nd|rd|th)?, YYYY`
  5. `M월 D일`
  6. `M/D`, `M.D`
  - 바로 뒤의 요일(`(월)` 또는 붙은 `월`·`화`…)은 함께 먹는다. 그래야 '11/9월~11/11수'의 '9월'을 '9월'로 잘못 읽지 않는다.
  - `-`는 `YYYY-MM-DD`에서만 날짜 구분자로 본다('2026-1학기', '1-2학년'을 날짜로 읽지 않기 위해).
  - 기간: `A ~ B`, `A – B`, `A - B`, `A부터 B까지`, `~B`. 끝 날짜는 B다. B가 일만 있으면(`24(금)`) A의 달을 쓴다.
  - 시각(`HH:MM`, `HH시`, `오전 9시`)은 무시한다. 월 1~12, 실제 달력에 있는 날만 받는다(`2.0 이상` 같은 줄은 day 0이라 버린다).
  - 연도가 없으면 게시일 연도를 붙이고, 게시일보다 60일 넘게 앞서거나 그 해에 없는 날(2/29)이면 다음 해로 넘긴다.
  - 코드 리뷰 뒤 더한 것: 'M월 D(요일)'(일 없이 요일이 바로 붙음), '~ 30일'처럼 일 뒤에 '일'이 붙은 끝, 끝 날이 앞 날보다 작으면 다음 달('4/28~2(토)'). 'M.D'는 영어 낱말 바로 뒤의 점 숫자('Llama 3.1'), 뒤 'N월 N일'의 달과 붙은 목록 번호('1. 11월 15일'), 소수('3.5 이상', '3.5점')를 날짜로 보지 않는다.
- **Rationale**: 표본에서 본 꼴이 모두 들어간다. 같은 날이 표기만 다른 경우(3건)는 날짜로 바꾼 뒤 비교하니 엇갈림으로 잡히지 않는다.
- **Alternatives considered**: `Date`·`Intl`(한국어 꼴을 못 읽음), 날짜 라이브러리(새 의존성이고 한국어 규칙은 결국 직접 써야 함).

## R7. 마감 고르기와 근거

- **Decision**:
  - 후보는 차례로 본다: 본문 신청 줄 → 제목 → 행사 날(종류가 특강일 때만).
  - 제목에서는 마감 표시가 있는 날짜만 마감으로 본다: `~` 뒤의 날짜, 기간의 끝, 신청·접수·마감·까지가 붙은 날짜. 괄호 속 날짜 하나(`(5/27, 수, 12시)`, `(11/18 10:30)`)는 행사 날이고 특강에만 쓴다. 예: '진학설명회 안내 (9/30(목) 18:00 / 사전접수 : 9/18(금))'는 9/18이다.
  - 신청 줄로 보는 라벨: 신청기간·신청 기간·신청 마감, 접수기간·접수 마감, 모집기간·모집 기간·모집일정, 지원기간·지원 기간·지원 마감, 제출기간·제출 기한, 서류 마감, 사전등록, 마감, 기한. '~까지'는 신청·접수·제출·지원과 같은 줄에 있을 때만 쓴다.
  - 자격·대상·출생이 있는 줄과 행사 줄(일시, 교육기간, 활동기간, 행사기간, 운영기간, 실습기간, 면접, 발표)은 건너뛴다. 줄 앞 라벨 쪽(첫 날짜 앞)만 보고 정한다.
  - 줄 하나의 후보: 라벨 뒤 날짜에서 기간의 끝(물결표·줄표·'부터'로 이은 뒤 날짜)을 쓰고, 한 줄에 서로 다른 기간 끝이 둘이면 엇갈림이다. 기간이 없으면 첫 날짜다. 마지막 날짜 바로 뒤에 끝을 못 읽은 물결표·'부터'가 있으면 그 줄은 쓰지 않는다.
  - 라벨만 있고 날짜가 없는 제목줄(글자 수가 라벨 글자 + 4 이하)이거나 끝을 다음 줄에 적은 기간이면 다음 줄의 날짜를 쓴다. '~까지' 줄의 '지원'은 '지원됩니다·지원금'을 빼고 본다.
  - 제목은 마감 표시를 뒤에서부터 보고, 뒤에 날짜가 있는 첫 표시의 날짜를 쓴다(기간이면 끝). 행사 날의 본문 일시 줄은 마지막 날짜(여러 날이면 끝나는 날)다.
  - 신청 줄에서 나온 끝 날짜가 서로 다르면 빈칸이다. 다만 그 후보 가운데 제목의 마감 표시 날짜가 있으면 그 날짜다(T032, CJ제일제당 '~9/30'). 고른 날짜가 게시일보다 앞서도 빈칸이다.
  - 마감 근거 값은 정해진 말만 쓴다: `본문: <라벨>`(예: `본문: 접수기간`), `제목`, `본문·제목`, `행사 날: 제목`, `행사 날: 본문`.
- **Evidence (본문 49건)**: 같은 줄에 날짜가 있는 신청 줄 20건, 다음 줄 2건, 그림뿐 9건(그중 5건은 제목에 날짜), 표기만 다른 같은 날 3건, 자격 줄 날짜 1건(출생일 기준), '경영지원' 함정 1건.

## R8. 주최

- **Decision**: 제목 맨 앞 `[…]`. 안에 꼬리표 단어(특강, 안내, 강연, 학기, 졸업, 모집, 인턴, 추천, 공고, `제N회`)가 있으면 버린다. 없으면 제목의 `○○ 주최`. 그래도 없으면 null.
- **Rationale**: 본문 49건에 '주최:' 줄이 0건이었다. 회사·사업단 이름은 대부분 제목 대괄호에 있다.

## R9. 중복 정리

- **Decision**: 제목에서 날짜·시각 토큰, 요일 표시, `~`, 비게 된 괄호를 지우고 공백을 모두 뺀 것을 열쇠로 쓴다(공백 하나만 다른 다시 올린 글: 현대해상 2건). 열쇠와 마감(빈칸 아님)이 같은 기회끼리 묶어 글 번호가 가장 큰 것만 남긴다. 합친 수는 요약의 M이다.
- **Evidence**: SSAFY 16기 모집(216747 '(~5/11)', 217063 '(~5/11월)')은 합쳐지고, KB국민은행 3건(디지털·IT·AI·플랫폼개발 부문)은 열쇠가 달라 남는다.

## R10. 결과 파일 쓰기

- **Decision**: JSON(들여쓰기 2칸, 끝 줄바꿈). 기회와 확인 필요를 각각 글 번호 큰 순으로 정렬한다. `cse-notices.json.tmp`에 쓴 뒤 이름을 바꾼다(같은 디스크 안 이름 바꾸기는 한 번에 일어난다). `collectedAt`은 ISO 시각이다. 이것 말고는 같은 입력이면 같은 파일이다.
- **Alternatives considered**: 바로 쓰기(쓰다가 죽으면 반쪽 파일, 바꾸기와 코드 길이가 같아 더 안전한 쪽을 택함), 한 줄 한 건 JSON(사람이 읽기 불편).

## R11. 정답셋 도구와 CSV

- **Decision**:
  - `eval.ts new <시작일> <끝날> [개수]`는 목록에서 기간 안 글을 모아 초안 CSV를 만든다. 링크·게시판·제목·게시일을 채우고 라벨 칸은 비운다. 비교는 이 네 값과 보관한 본문으로 판정해서, 다시 돌려도 결과가 같다. 그 글들의 본문은 보관함에 받아 둔다. 개수를 주면 글 식별자의 SHA-1 해시(`node:crypto`) 순서로 앞에서부터 고른다. 다시 돌려도 같은 표본이 나오는 무작위 추출이다.
  - `eval.ts <정답셋.csv>`는 비교한다.
  - 쓰기: UTF-8 + BOM, 줄 끝 CRLF, 모든 칸을 따옴표로 감싼다(엑셀 호환).
  - 읽기: BOM을 지운다. UTF-8(fatal)로 읽고, 실패하면 EUC-KR(`TextDecoder('euc-kr')`, 로컬에서 동작 확인)로 다시 읽는다. 따옴표·쉼표·줄바꿈이 든 칸을 RFC 4180대로 읽는다.
  - 받는 값:
    - 날짜: `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD`, `YYYY. M. D.`
    - 마감 칸: `없음`, `그림·첨부`
    - 기회: `O`/`X`(소문자 포함)
    - 종류: 한글 이름 11종
  - 틀린 값이 있으면 줄 번호와 값을 모두 모아 보여 주고 2로 끝난다(contracts/cli.md 종료 코드).
  - 초안 라벨은 Claude가 보관한 본문을 읽고 CSV에 직접 적는다. CSV에 본문 문장은 넣지 않는다.
- **Alternatives considered**: 구글 시트(로컬 전용 원칙 밖), TSV(맥 엑셀 열기가 불편), JSON(사람이 고치기 어려움).

## R12. 지표 계산

- **Decision**: SC-001~SC-007과 주최 채움 비율을 순수 함수 하나로 계산한다. 분모는 spec의 정의 그대로이고, 분모가 0이면 그 항목은 '해당 없음'이다. 항목마다 틀린 글 목록(식별자, 규칙 값, 정답 값, 근거)을 함께 낸다.
