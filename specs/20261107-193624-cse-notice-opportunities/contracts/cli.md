# CLI 계약: 수집 명령과 정답셋 명령

**Feature**: [../spec.md](../spec.md) · 실행 환경은 Node 22.18 이상([../research.md](../research.md) R1). 저장소 루트에서 실행한다.

## 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 성공. 정답셋 비교는 모든 기준을 통과함 |
| 1 | 실행 실패(목록 못 받음, 게시판 구조 변경). 정답셋 비교는 기준 미달 |
| 2 | 잘못된 입력(인자 꼴, 정답셋 값 오류, 덮어쓰기 거부) |

실패 메시지는 표준 오류에 한국어 한 줄로 쓴다. 진행 표시(목록 몇 쪽째, 본문 몇 건째)도 표준 오류에 쓰고, 표준 출력에는 결과 요약만 쓴다.

## `node etl/notices/run.ts [기준일]`

- **기준일**: `YYYY-MM-DD`. 그날 올라온 글을 포함한다. 생략하면 실행한 날(컴퓨터 날짜)의 90일 전이다.
- **하는 일**: 목록 읽기 → 보관에 없는 본문만 받기 → 판정 → 중복 정리 → `etl/out/cse-notices.json`을 통째로 바꾸기([cse-notices.schema.json](./cse-notices.schema.json)). 폴더가 없으면 만든다.
- **표준 출력** (성공 시 한 줄):

  ```text
  새 글 3 · 기회 96 · 기회 아님 21 · 확인 필요 9 · 합친 중복 1 · 마감 빈칸 14
  ```

  `기회 + 기회 아님 + 확인 필요 + 합친 중복` = 기준일 안 글 수.

  스펙 2(로컬 LLM 판정, [../../20261109-165520-notice-llm-judge/contracts/llm.md](../../20261109-165520-notice-llm-judge/contracts/llm.md))부터 LLM을 쓴 실행은 끝에 `· LLM 판정 L(보관 A · 새로 B · 실패 C)`가 붙는다. LLM 서버에 닿지 못해 규칙만 쓴 글이 K건(K>0)이면 다음 줄에 `LLM에 연결하지 못해 K건은 규칙만 썼어요 (<모델>)`가 나온다. LLM 문제로는 종료 코드가 바뀌지 않는다. 환경 변수: `KINGO_LLM_MODEL`(판정 모델), `OLLAMA_HOST`(Ollama 주소).
- **실패**:

  | 경우 | 표준 오류 | 코드 | 결과 파일 |
  |---|---|---|---|
  | 기준일 꼴이 틀림(달력에 없는 날, 인자 둘 이상 포함) | `기준일은 YYYY-MM-DD 꼴로 주세요: <값>` | 2 | 그대로 |
  | 목록 요청 실패(응답 없음·2xx 아님·15초 초과) | `목록을 받지 못했어요 (<offset>번째부터): <이유>. 이전 결과는 그대로예요.` | 1 | 그대로 |
  | 목록 쪽에서 글을 하나도 못 읽음(어느 쪽이든. 기간 안 글이 없는 것은 오류가 아님) | `게시판 구조가 바뀐 것 같아요: 목록에서 글을 하나도 못 읽었어요. 이전 결과는 그대로예요.` | 1 | 그대로 |
  | 받으려 한 본문 2건 이상에서 본문을 하나도 못 얻음, 받은 페이지에 본문 영역이 없음 | `게시판 구조가 바뀐 것 같아요: 새로 받은 본문 <n>건에서 본문 영역을 못 찾았어요. 이전 결과는 그대로예요.` | 1 | 그대로 |
  | 받으려 한 본문 2건 이상이 모두 받기 실패 | `본문을 하나도 받지 못했어요 (<n>건 모두 실패). 이전 결과는 그대로예요.` | 1 | 그대로 |

  본문 한 건이 실패하면 멈추지 않는다. 그 글은 `review`에 `본문 못 받음`으로 들어간다.

## `node etl/notices/eval.ts new <시작일> <끝날> [개수]`

- 목록에서 `<시작일>`~`<끝날>`(둘 다 포함)에 올라온 글을 모은다. 그 글들의 본문을 보관함에 받아 두고, 정답셋 초안 CSV를 `etl/gold/draft-<시작일>-<끝날>.csv`에 쓴다([gold-csv.md](./gold-csv.md)). 라벨 칸은 비어 있다.
- **개수**를 주면 글 식별자의 SHA-1 해시 순서로 앞에서 그만큼 고른다(다시 돌려도 같은 표본). 주지 않으면 전부 쓴다.
- 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 코드 2로 끝난다. 사람이 고친 라벨을 지키기 위해서다. 시작일이 끝날보다 뒤여도 코드 2다.
- 본문을 한 건이라도 받지 못하면 초안을 쓰지 않고 코드 1로 끝난다: `본문 <n>건을 받지 못해 초안을 쓰지 않았어요 (글 번호 …). 다시 실행하면 받아 둔 본문은 건너뛰어요.` 비교가 늘 같은 본문으로 돌게 하려는 것이다.
- **표준 출력**: `초안 <n>줄: etl/gold/draft-…csv`

## `node etl/notices/eval.ts <정답셋.csv>`

- 정답셋 줄의 제목·게시판·게시일과 보관한 본문으로 규칙을 돌린다. 본문이 보관에 없으면 받는다. `run.ts`와 같은 판정 함수를 쓴다.
- **표준 출력**: 지표 표와 항목별 틀린 글 목록.

  ```text
  지표          값      기준     판정
  기회 여부     97.6%   ≥95%    통과   (245/251)
  기회 놓침      2.1%   ≤3%     통과   (4/188)
  종류          91.2%   ≥90%    통과
  마감 정확     96.0%   ≥95%    통과
  마감 채움     74.5%   ≥70%    통과
  주최          93.0%   ≥90%    통과
  확인 필요      8.5%   ≤10%    통과
  주최 채움(참고) 61.0%

  [종류 틀림] cse:225249 규칙=lecture 정답=job 근거=제목: 설명회
  …
  ```

- 값 오류가 있으면 비교하지 않고 모든 오류를 `<줄>행 <칸>: <값> (<이유>)` 꼴로 보여 준 뒤 코드 2로 끝난다. 글이 한 줄도 없으면 `정답셋에 글이 없어요: <경로>`, 코드 2다.
- 본문을 읽지 못한 줄이 있으면 점수를 내지 않고 코드 1로 끝난다: `본문 <n>건을 읽지 못해 비교하지 않았어요 (글 번호 …).` 받기 실패를 규칙의 '확인 필요'로 세지 않기 위해서다.
