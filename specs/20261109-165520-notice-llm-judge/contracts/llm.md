# LLM 판정 계약

**Feature**: [../spec.md](../spec.md) · **Data model**: [../data-model.md](../data-model.md)

## 요청 (Ollama `/api/chat`)

```json
{
  "model": "<KINGO_LLM_MODEL>",
  "stream": false,
  "think": false,
  "keep_alive": "10m",
  "options": { "temperature": 0, "num_ctx": 16384 },
  "format": { "type": "object", "properties": { "기회": {"enum": ["O", "X"]}, "종류": {"enum": ["채용", "특강", "해커톤", "대회·공모전", "교육·캠프", "동아리·학회", "봉사", "멘토링", "글로벌", "장학", "교과", ""]}, "주최": {"type": "string"}, "확신": {"enum": ["높음", "낮음"]} }, "required": ["기회", "종류", "주최", "확신"] },
  "messages": [
    { "role": "system", "content": "<지시문: 정답 기준, 종류 표, 우선순위, 애매한 글 기준, 주최 규칙, 예시>" },
    { "role": "user", "content": "<글: 아래 '사용자 메시지' 꼴>" }
  ]
}
```

- 주소: `OLLAMA_HOST`를 아래 '설정'대로 읽은 값 + `/api/chat`. 글당 120초 제한, 한 번에 하나.
- 모든 후보 모델에 같은 `think`·`options`를 쓴다(문맥 길이 16384 고정).
- 지시문 재료: 스펙 1 [gold-guide.md](../../20261107-193624-cse-notice-opportunities/gold-guide.md) 1절(기회 O/X, 정해 둔 기준), 2절(종류 11종 뜻 표, 좁은 쪽 우선 순서, 예시 제목 표), 4절(주최). 마감(3절)은 넣지 않는다. 끝에 'JSON 하나로만 답한다', '날짜는 쓰지 않는다', '주최에 사람 이름을 쓰지 않는다'를 둔다.

### 판

- 글 내용(게시판, 제목, 본문 줄)만 뺀 요청 전체의 SHA-1 앞 8자리다: 지시문, 답 스키마, 사용자 메시지 틀, 자르기 한도(60·120·300·8,000), `think`·`options`. 무엇을 바꾸든 판이 바뀌고, 옛 판의 답은 쓰지 않는다.

### 사용자 메시지

```text
게시판: 채용/모집
제목: [SK그룹] Pre-SKALA 참여자 모집 (~10/14 09시까지)
본문 글자 12줄:
| …
```

- 본문 줄은 research R3대로 자른다(앞 60줄 + 날짜·신청 단어 줄, 120줄까지, 줄당 300자, 합쳐 8,000자). 글자가 없으면 `본문 글자 없음(그림·첨부뿐)`.
- 규칙 결과나 다른 글은 보내지 않는다. 본문을 받지 못한 글은 묻지 않는다.

## 답 검사

| 칸 | 받는 값 | 아니면 |
|---|---|---|
| (전체) | JSON 객체 하나. 앞뒤의 ```` ``` ````·```` ```json ```` 표시는 벗긴다 | 실패 |
| 기회 | `O`, `X` | 실패 |
| 종류 | O면 11종 이름 중 하나(가운뎃점까지 그대로). X면 무엇이든 버린다 | O인데 모르는 이름이거나 빈 값이면 실패 |
| 주최 | 문자열. 앞뒤 공백을 정리하고 빈 값·'없음'은 없음. X면 버린다. 결과에는 쓰지 않는다(주최는 제목 규칙 값, spec FR-001). 40자를 넘으면 없음으로 버린다 | 실패 아님 |
| 확신 | `높음`, `낮음` | 실패 |

- 날짜 칸은 없다. 답에 날짜가 있어도 쓰지 않는다(FR-007).

## 실패 구분

| 경우 | 결과 | 그 실행의 다음 글 |
|---|---|---|
| HTTP 응답을 받기 전에 난 `fetch` 오류 전부(연결 거부, `ENOTFOUND`, 연결 제한 시간, 연결 끊김, URL 꼴이 아닌 주소), HTTP 404(모델 없음) | `'down'` | 서버를 부르지 않음. 보관한 답은 읽고, 없으면 `'down'` |
| 서버에 닿은 뒤의 120초 시간 초과(`TimeoutError`), 404가 아닌 HTTP 오류, 답 검사 실패 | `'fail'` | 계속 물음 |

- 실패한 답은 보관하지 않는다. 다시 시도하지 않는다.
- `'down'`인 글은 처음 것을 포함해 모두 K(`skipped`)에 센다.

## 설정

| 환경 변수 | 없을 때 | 읽는 법 |
|---|---|---|
| `KINGO_LLM_MODEL` | US2로 고른 기본 모델(처음 값 `gemma-4-longctx:latest`) | 그대로 |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | Ollama 클라이언트처럼: 스킴이 없으면 `http://`, 포트가 없으면 `:11434`, 끝의 `/`는 뺀다. `https://`는 그대로. 예: `0.0.0.0` → `http://0.0.0.0:11434`, `localhost:8080` → `http://localhost:8080` |

## 보관

- `etl/.cache/llm/<모델>/<판>/<글번호>.json`(data-model LlmCacheFile). `.tmp`에 쓴 뒤 이름을 바꾼다.
- 같은 글·모델·판이면 서버에 묻지 않는다.

## 실행 명령의 바뀐 곳 (스펙 1 contracts/cli.md에 더함)

- 명령과 종료 코드는 그대로다. LLM 문제로는 종료 코드가 바뀌지 않는다(0으로 끝나고 결과 파일을 쓴다).
- 환경 변수: `KINGO_LLM_MODEL`(판정 모델), `OLLAMA_HOST`(Ollama 주소).
- 표준 출력 요약: `새 글 N · 기회 X · 기회 아님 Y · 확인 필요 Z · 합친 중복 M · 마감 빈칸 W · LLM 판정 L(보관 A · 새로 B · 실패 C)`
- 서버에 닿지 못해 규칙 결과로 낸 글이 K건(K>0)이면 다음 줄: `LLM에 연결하지 못해 K건은 규칙만 썼어요 (<모델>)`. K가 0이면 없다.
- 진행 표시(표준 오류): `LLM 20/150` 꼴로 20건마다.

## 정답셋 비교의 바뀐 곳 (`node etl/notices/eval.ts <정답셋.csv>`)

- 실행과 같은 판정 경로로 판정한다(FR-023). 지표 표 위에 `LLM 판정 L(보관 A · 새로 B · 실패 C)` 줄을 찍는다.
- 서버에 닿지 못한 글이 K건(K>0)이면 지표를 내지 않고 표준 오류에 `LLM에 연결하지 못한 글이 K건이라 비교하지 않았어요 (<모델>)`를 쓰고 종료 코드 1로 끝낸다.
- 글 판정 실패(C)는 규칙 결과로 점수에 넣는다. C>0이면 지표 표 아래에 `LLM 판정 실패 C건은 규칙 결과로 셌어요`를 쓴다.

## 결과 파일 계약의 바뀐 곳 (스펙 1 contracts/cse-notices.schema.json)

- `opportunities[].rule` 패턴: `^(제목|게시판|LLM): .+$`
- `review[].why`에 `LLM 확신 낮음`이 올 수 있다(패턴 없음, 그대로).
