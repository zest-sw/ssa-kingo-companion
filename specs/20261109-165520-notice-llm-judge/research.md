# Research: 공지 판정에 로컬 LLM 더하기

**Feature**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md) · 스펙 1 [research.md](../20261107-193624-cse-notice-opportunities/research.md)

## R1. LLM 서버와 호출 방식

- **Decision**: 이 컴퓨터의 Ollama(0.32.0)를 `/api/chat`으로 부른다. `stream: false`, `think: false`, `options: { temperature: 0, num_ctx: 16384 }`, `format`에 JSON 스키마를 준다. 호출은 Node 내장 `fetch`와 `AbortSignal.timeout(120000)`.
  - 문맥 길이를 요청에 고정해 모든 후보가 같은 조건에서 답한다. 16384는 사용자가 만든 `gemma-4-longctx`의 설정 값이고, 지시문(약 3천 토큰)과 본문 8,000자(R3)를 담는다.
- **Rationale**: 사용자가 브레인스토밍에서 로컬 모델을 골랐다(외부 API 키·요금 없음, 본문이 밖으로 안 나감). Ollama는 이미 설치돼 서버가 떠 있고 HTTP API라 새 의존성이 없다. JSON 스키마를 주면 칸과 값(종류 11종 enum)을 서버가 묶어 준다.
- **Evidence (2026-11-09 시험)**:
  - 스키마를 준 호출이 `{"기회": "O", "종류": "채용", "주최": "토스", "확신": "높음"}` 꼴로 답했다. 첫 호출 5.7초(모델 올리기 4.8초), 입력 51토큰, 출력 32토큰.
  - 없는 모델은 HTTP 404 `{"error":"model '…' not found"}`.
  - 서버가 꺼져 있으면 `fetch`가 `TypeError`(cause.code `ECONNREFUSED`)를 바로 던진다.
- **Alternatives considered**: Claude API(키·요금 필요, 사용자가 로컬을 원함), `claude -p`(느리고 구독 한도), `/api/generate`(chat과 같지만 system·user 구분이 덜 분명함), MLX·llama.cpp 직접(설치가 늘어남).

## R2. 후보 모델

- **Decision**: 이미 받아 둔 Gemma 4 E4B 하나와, 한국어에 강한 7~14B급 한두 개를 비교한다. Claude가 Ollama 목록에서 새 후보를 크기·메모리·라이선스와 함께 제안하고, 사용자가 확인한 뒤 내려받는다(FR-019).
  - `gemma-4-longctx:latest`와 `hf.co/ggml-org/gemma-4-E4B-it-GGUF:latest`는 같은 가중치다. longctx 매니페스트(`~/.ollama/models/manifests/registry.ollama.ai/library/gemma-4-longctx/latest`)의 모델 층이 E4B GGUF와 같고(`sha256:90ce9812…`), 다른 것은 매개변수 `{"num_ctx":16384,"stop":["<turn|>"]}`뿐이다. 요청에 `num_ctx`를 고정하므로(R1) 후보 하나로 세고, 기본 모델 이름은 짧은 `gemma-4-longctx:latest`를 쓴다.
- **Rationale**: 메모리 24GB에서 14B급(Q4 약 9GB)까지는 다른 앱과 함께 돌고, 27~32B급은 빠듯하다. 모델 크기와 한국어 능력에 따라 경계 판단이 크게 달라 재 보고 고른다.
- **Alternatives considered**: 하나만 쓰기(재 보지 않으면 스펙 1처럼 처음 보는 글에서 미달할 위험), 27~32B(메모리·속도 부담).

## R3. LLM에 보내는 글

- **Decision**: 제목, 게시판 분류, 본문 글자 줄. 본문은 앞 60줄과 그 뒤 줄 중 숫자·신청·접수·마감·기간·까지·일시·모집·지원·제출·대상·주최·주관·장소가 든 줄로, 모두 합쳐 120줄까지, 한 줄은 300자까지, 전체 8,000자까지 자른다. 본문 글자가 없으면 그렇다고 적는다. 본문을 받지 못한 글은 보내지 않는다.
- **Rationale**: 정답셋 라벨러(Claude·codex)가 본 덤프와 같은 꼴이다(스펙 1 [gold-guide.md](../20261107-193624-cse-notice-opportunities/gold-guide.md) '입력' 절: 식별자·게시일·게시판·제목, 그림·첨부 수, `| `로 시작하는 본문 줄, 앞 60줄과 날짜·신청 단어 줄 120줄까지). LLM이 라벨러와 같은 정보로 판단해야 정답셋 비교가 공정하다. 8,000자 한도는 문맥 길이(R1)에 맞춘 것으로, 정답셋 덤프에서는 거의 걸리지 않는다.
- **Alternatives considered**: 본문 전체(긴 글은 수천 토큰이라 느림), 제목만(스펙 1 규칙과 같은 한계).

## R4. 지시문과 판

- **Decision**: 지시문 재료는 스펙 1 [gold-guide.md](../20261107-193624-cse-notice-opportunities/gold-guide.md) 한 곳에서 가져온다: 1절(기회 O/X와 정해 둔 기준), 2절(종류 11종 뜻 표, 좁은 쪽 우선 순서, 예시 제목 표), 4절(주최). 3절(마감)은 LLM이 마감을 정하지 않아 넣지 않는다. 판은 글 내용만 뺀 요청 전체(지시문, 답 스키마, 사용자 메시지 틀, 자르기 한도 60·120·300·8,000, `think`·`options`)를 합친 SHA-1 앞 8자리다.
- **Rationale**: 손으로 판을 올리면 잊기 쉽다. 요청 전체를 해시하면 무엇을 바꾸든 판이 바뀌어 옛 답을 쓰지 않는다(FR-003, FR-009, FR-010). 정답셋 라벨러와 LLM이 같은 기준 문서를 읽어야 비교가 공정하다.
- **Alternatives considered**: 손으로 매기는 판 번호(잊으면 옛 답이 섞임).

## R5. 답 검사

- **Decision**: 답 글자에서 코드 블록 표시를 벗기고 JSON으로 읽는다. 기회는 O/X, 종류는 11종 이름(가운뎃점까지) 중 하나, 주최는 문자열(앞뒤 공백 정리, 빈 값은 '없음', 40자 넘으면 실패), 확신은 높음/낮음. 기회가 X면 종류·주최를 버린다. 하나라도 어기면 실패다.
- **Rationale**: 스키마가 서버 쪽에서 묶어도 모델·버전에 따라 어길 수 있다. 검사한 값만 타입을 붙여 쓴다(G2). 주최 길이 제한은 본문 문장을 옮겨 적은 답을 막는다(G5).

## R6. 보관

- **Decision**: `etl/.cache/llm/<모델>/<판>/<글번호>.json`에 `{ model, prompt, at, answer }`를 쓴다. 모델 이름의 `/`·`:` 같은 글자는 `_`로 바꾼다. 쓸 때는 `.tmp`에 다 쓴 뒤 이름을 바꾼다(스펙 1 본문 보관과 같다). 성공한 답만 쓴다.
- **Rationale**: 같은 글·모델·판이면 다시 묻지 않고(FR-009), 모델을 바꾸면 그 모델 답만 쓴다. 파일 하나에 글 하나라 반쯤 쓰다 멈춰도 다른 답이 깨지지 않는다.

## R7. 실패 처리

- **Decision**: 실패를 둘로 나눈다.
  - **꺼짐(`'down'`)**: HTTP 응답을 받기 전에 난 `fetch` 오류 전부(연결 거부, 주소 해석 실패 `ENOTFOUND`, 연결 제한 시간 `UND_ERR_CONNECT_TIMEOUT`, 연결 끊김, URL 꼴이 아닌 주소)와 HTTP 404(모델 없음). 그 실행에서는 서버를 다시 부르지 않는다(FR-015). 보관한 답은 계속 읽는다.
  - **글 실패(`'fail'`)**: 서버에 닿은 뒤의 120초 시간 초과(`TimeoutError`), 404가 아닌 HTTP 오류, 답 검사 실패. 그 글만 규칙 결과(FR-013). 다시 시도하지 않는다.
- **Rationale**: 서버가 꺼졌거나 주소가 틀린 날 글마다 기다리면(닿지 않는 주소는 연결 제한 10초) 150건이면 25분이 늘어난다. 처음 한 번만 기다리고 끊어서 SC-009(10초 안)를 지킨다.

## R8. 판정 묶기와 비교

- **Decision**:
  - run.ts의 `judge(글, 본문, LLM 판정?)`은 지금처럼 동기·순수 함수로 두고, LLM 판정이 있으면 규칙 판정 대신 쓴다. 마감은 최종 종류로 `deadlineOf`를 부른다(FR-007). 주최는 LLM 판정이 있으면 그 값, 없으면 `hostOf`.
  - `judgeAll(글들, 본문들, ask?)`이 보낼 글을 고르고(`LLM_ROUTE`), 차례로 묻고, 요약 수를 센다. `main`과 `eval.ts` compare가 이것을 쓴다(FR-023).
  - `ask`는 바깥에서 넣는다. `main`은 설정으로 만든 기본 ask를, 검사는 가짜를 넣는다(스펙 1의 `Get`과 같은 방식).
- **Rationale**: 실행과 비교가 같은 경로를 써야 비교 성적이 실제 결과와 같다.

## R9. 설정

- **Decision**: `KINGO_LLM_MODEL`(없으면 US2로 고른 모델 이름 상수)과 `OLLAMA_HOST`(Ollama 클라이언트와 같은 변수). `OLLAMA_HOST`는 Ollama 클라이언트처럼 읽는다: 없으면 `http://127.0.0.1:11434`, 스킴이 없으면 `http://`, 포트가 없으면 `:11434`, 끝의 `/`는 뺀다. `https://`로 시작하면 그대로 쓴다. 예: `0.0.0.0` → `http://0.0.0.0:11434`, `localhost:8080` → `http://localhost:8080`.
- **Rationale**: 모델은 컴퓨터 사양과 시기에 따라 바뀐다. 한 곳에서만 정해 나중에 관리자 화면이 바꿀 자리로 둔다(spec 후속 작업).

## R10. 보낼 글 방식과 확신 '낮음' 처리

- **Decision**: 상수 두 개(`LLM_ROUTE`: `review` | `all`, `LLM_LOW`: `accept` | `review`)를 두고, `judgeAll(…, route = LLM_ROUTE, low = LLM_LOW)`과 `fromLlm(answer, model, low = LLM_LOW)`의 기본값으로만 쓴다. 실행(`main`)과 정답셋 비교(`eval.ts`)는 기본값을 쓰고, 조합 비교 임시 스크립트는 같은 함수에 네 조합의 값을 넘긴다. 그래서 조합 고르기도 실행과 같은 판정 경로다(FR-023). 비교 중에는 `LLM_ROUTE` 상수를 잠시 `all`로 두어 개발용 전체 답을 보관한다. US2 비교 뒤 두 상수의 값을 굳힌다.
- **Rationale**: 환경 변수 같은 실행 설정은 늘리지 않는다(아무도 안 바꾸는 손잡이, plan Complexity Tracking). 기본값 인자는 검사와 비교 스크립트가 두 값을 모두 돌리기 위한 것이다. 비교 결과는 이 문서 R12에 적는다.

## R11. 평가 절차

- **Decision**:
  - 개발용 501건: 스펙 1 `etl/gold/dev-2025-09-01-2026-11-06.csv`(401건)와 `etl/gold/draft-2025-05-01-2025-08-31.csv`(100건)를 합친 파일. 지시문은 개발용만 보고 다듬는다.
  - 최종 평가용: `node etl/notices/eval.ts new 2025-01-01 2025-04-30 100`. 스펙 1 FR-032와 같은 교차 라벨로 확정하고 고른 조합으로 한 번만 잰다. 측정 전까지 누구도 이 100건에 규칙이나 LLM을 돌리지 않는다.
  - 기준은 SC-001~SC-007(스펙 1과 같은 정의). 비교 지표에 개발용 전체를 LLM으로 판정한 시간(글당 평균)도 적는다.
- **Rationale**: 스펙 1과 같은 절차라 성적을 나란히 볼 수 있다.

## R12. 비교 결과
