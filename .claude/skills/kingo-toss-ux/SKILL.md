# 토스 수준 UX 기준 (킹고 컴패니언판)

토스 제품 원칙의 한가운데는 Simplicity다. 사용자가 따로 알거나 배우지 않아도 바로 쓰는 상태를 말한다(https://toss.im/tossfeed/article/tossproductprinciples, 2025-09).
이 프로젝트의 기존 기준(CLAUDE.md: 4px 반경, 얇은 1px 선, SKKU 색 절제, 점수·비교 금지, 진입점 하나, 페이지 스크롤 0)이 언제나 이긴다. 토스의 큰 둥근 카드나 밝은 파랑 같은 모양은 가져오지 않는다. 단순함, 위계, 움직임, 말의 완성도를 가져온다.

## 1. 토스 원칙 10가지를 우리 화면 기준으로
| # | 원칙 | 우리 화면에서 확인할 것 |
|---|---|---|
| 01 | Casual Concept | 배워야 쓰는 개념이 화면에 있나? 그림마다 읽는 법 한 줄(해석 문장)과 범례. 내부 용어(노드, 엣지, 클러스터, 규칙 n, 가중치) 금지. |
| 02 | Simple Policy | 조건·규칙을 늘어놓지 않는다. 에이전트가 확인하고 결과만 말한다('신청 대상이에요'). |
| 03 | Value First | 입력·설정을 받기 전에 얻는 것부터 보여 준다(신청 준비 전 '얻는 것', 가입 전 예시). |
| 04 | Clear Action | 글을 읽지 않아도 다음 행동이 보이나? 화면당 주 버튼 하나. 흐름 화면에서는 늘 같은 자리에 둔다. |
| 05 | Context Based | 앞 화면에서 무엇을 하다 왔는지 이어지나? 회고 저장 다음은 분석, 신청 준비 다음은 일정. 상황(마감 임박, 하는 중, 회고 대기)에 맞는 것만 위로 올린다. |
| 06 | Easy to Answer | 묻는 말에 3초 안에 답할 수 있나? 고르기 어려우면 추천값을 미리 고르고, 기억해야 하는 것은 에이전트가 채운다. 어려운 질문 하나보다 쉬운 질문 셋, 없으면 더 좋다. |
| 07 | Explain Why | 왜 해야 하는지 말했나? 추천에는 이유 한 줄, 확인 요청에는 '맞다고 하면 무엇이 바뀌는지'. |
| 08 | One Thing | 한 화면에 핵심 메시지 하나. 첫눈에 들어오는 주인공 하나(가장 크고 진하게), 나머지는 조연(작고 옅게). |
| 09 | No More Loading | 기다림을 없앤다. 300ms를 넘을 때만 로딩을 보이고, 뼈대는 실제 모양 그대로 둔다(레이아웃 이동 0). 미리 계산할 수 있는 건 미리 한다. |
| 10 | Minimum Features | 이 기능 없이 핵심 일(다음 활동 고르기, 나를 이해하기, 신청 준비)을 못 하나? 아니면 뺀다. 기능 추가는 마지막 수단이다. |

UX 원칙(「유난한 도전」 요약)도 같이 본다: One thing per one page, Tap & Scroll(핵심 흐름은 누르기와 세로로 넘기기만), Easy to Answer, Value first cost later.

## 2. 데스크톱 레퍼런스에서 가져올 것
- **Linear, A calmer interface(2026-03)**: 모든 요소가 같은 무게를 갖지 않는다. 일하는 본문이 앞에 서고, 길 찾기(사이드바, 탭, 머리말)는 한두 단계 옅게 물러난다. 머리말·탭·보기 조절은 모든 화면에서 같은 자리, 같은 모양이다. (https://linear.app/now/behind-the-latest-design-refresh)
- **토스증권 PC Design Platform**: 정보 밀도를 높이면서도 가독성과 직관성을 지키는 화면 구성 규칙을 컴포넌트 단위 가이드로 만든다. 화면마다 새로 그리지 않고 공용 부품을 쓴다. (https://toss.im/career/article/secu_pc_design_platform)
- **TDS 메뉴 컴포넌트 개선기**: 긴 목록은 위아래 흐림으로 더 있음을 알린다. 떠 있는 요소는 가볍게 보이게 한다(옅은 그림자, 얇은 외곽선). 누름에는 배경 한 단계 진해지는 피드백. 열고 닫을 때 초점을 옮기고, 아이콘 버튼 이름은 모양이 아니라 기능으로 붙인다. 글이 길어질 때와 큰 글씨에서도 깨지지 않게 한다. (https://toss.tech/article/toss-design-system)

## 3. 위계 (눈이 가는 순서를 설계한다)
- 글자 단계는 토큰만 쓴다. 굵기는 700/600/400 세 단계, 회색도 세 단계(본문, 보조, 옅음).
- 화면마다 주인공 하나를 정한다. 주인공 숫자·결론은 크게, 단위·설명은 작게(숫자는 tabular-nums).
- 같은 층위는 같은 모양이다. 카드 머리, 더 보기, 꼬리표, 범례는 공용 부품만 쓴다.
- 페이지 제목과 카드 제목이 같은 말이면 카드 제목을 지우거나 결론 문장으로 바꾼다.
- 여백은 4의 배수로 리듬을 만든다. 카드 안 24, 카드 사이 16~20, 제목과 내용 사이 12.
- 큰 면적 색 채우기 금지. 막대·띠는 얇게(8px 안팎) 또는 외곽선으로, 색은 의미가 있을 때만 쓴다.
- 빈 영역이 한쪽에만 크게 남으면(한 열은 꽉 차고 옆 열은 반만) 배치를 다시 잡는다. 열의 아래 끝을 맞추거나 한 열로 쌓는다.

## 4. 상호작용 완성도
- 모든 누를 수 있는 것에 hover(150ms), 눌림(active, 배경 한 단계 진하게), focus-visible 링을 준다.
- 사용자가 만든 변화만 움직인다(열림, 펼침, 확인, 넘김). 200~250ms ease-out으로 하고, 방향은 의미와 같게 한다. prefers-reduced-motion이면 바로 바꾼다.
- 되돌릴 수 있는 행동(관심 없음, 나중에 보기, 지우기)은 토스트와 되돌리기로 처리한다. 되돌릴 수 없으면 한 번 확인한다.
- 상태는 주소에 남긴다(탭, 필터, 모달). 새로고침하거나 링크를 열어도 같은 화면이 나와야 한다.
- 모달·서랍은 열 때 첫 초점, 닫을 때 원래 자리로 초점이 돌아온다. Esc로 닫힌다.

## 5. 화면마다 점검표 (보고에 한 줄씩)
| 화면 | 주인공 하나는? | 주 행동 하나는? | 문구만 읽고 3초 이해? | 배워야 하는 개념? | 빈·희소·밀집·오류 상태? |
