# 킹고 UI 리뷰 (끝내기 전 절차)

화면을 만들거나 고친 워커는 이 순서를 다 거친 뒤에만 "끝났다"고 말한다. "코드는 맞게 썼다"는 확인이 아니다.

## 1. 디자인 판단: frontend-design 을 먼저, 이 프로젝트 기준이 이긴다

- 시작할 때 `frontend-design` 스킬(`/frontend-design`)을 불러 위계·여백·타이포·한 곳에만 쓰는 강조를 판단한다. 스킬이 안 보이면 보고에 "frontend-design 없음"이라고 적고 이 문서만 따른다.
- 충돌하면 이 프로젝트가 이긴다: `CLAUDE.md`, `docs/design/web-desktop.md`, `docs/design/ia-navigation.md` 9절.
  - 4px 단위 간격, 얇은 선, 성균관대 색(네이비·그린·오렌지)은 토큰으로만, 절제해서. 새 글꼴·그라데이션·장식 그림자를 들이지 않는다.
  - 정보량 상한: 첫 화면 덩어리 3개, 덩어리 안 항목 5개, 버튼은 주 1 + 보조 2.
  - 단계·뎁스: 한 화면에 결정 하나. 이유·근거·표는 '자세히'(서랍 또는 하위 경로)로.
  - 점수·레벨·순위 없음, 육각형 차트 없음, 해요체 한 줄 안내.

## 2. 레이아웃 불변식 (하나라도 어기면 고친다)

1. **패널은 내용 높이.** 카드를 화면 높이에 맞춰 늘려 빈칸을 만들지 않는다. 남은 높이를 채우는 게 의도인 칸(목록, 지도, 보드 열, 흐름 화면의 결과 칸)만 채우고, 그 칸에는 `data-fill` 을 붙인다.
2. **행동 막대는 내용 흐름 안.** 버튼 줄이 카드 밖으로 나가거나 내용을 덮지 않는다. 고정 막대는 `Panel footer`(`data-action-bar`)로만, 막대 배경은 카드 가장자리까지 닿는다.
3. **한국어는 낱말 단위 줄바꿈.** 전역 `word-break: keep-all; overflow-wrap: anywhere`(base.css). 이름을 `…`로 자르지 말고 줄을 바꾼다. 꼭 잘라야 하면 `title` 로 전체를 준다.
4. **빈 상태 = 그림 틀 + 한 줄 + 버튼 하나.** 속이 찬 회색 띠(글자 없는 회색 막대)는 옆에 축 이름이 있어도 로딩 뼈대처럼 보여 쓰지 않는다. 그림 틀은 축·칸 테두리나 작은 그림으로 '여기에 무엇이 생기는지'를 보이고, 다음 행동을 말하는 해요체 한 줄과 버튼 하나를 둔다. 로딩(`LoadingState`)과 빈 상태가 같은 모양이면 안 된다.
5. **차트 이름표는 한 번.** 같은 차트에 같은 항목 이름이 두 번 나오지 않는다(마감·활동 날짜가 겹치면 한 줄에 두 표시로).
6. **글자 크기**: HTML 11px 이상, SVG 글자는 화면상 10.5px 이상.
7. **클릭 대상 32px 이상**, 키보드 포커스 링이 보인다. 칸 안 스크롤에서는 안쪽 링.
8. **페이지는 스크롤하지 않는다.** 1280×640 에서도. 넘치면 덜 중요한 걸 서랍으로, 그림을 작게, 목록만 칸 안 스크롤.
9. **본문 폭을 쓴다.** 카드 하나가 본문 왼쪽 절반에만 붙고 오른쪽이 비면 안 된다(폭을 채우거나 가운데 정렬 + 최대 폭).
10. **의도된 예외는 표시한다**: 차트 마커 위 이름표 겹침 `data-allow-overlap`, 줄마다 같은 이름이 나오는 차트 `data-allow-repeat`. 표시할 때는 이유를 주석 한 줄로.

## 3. 검사와 눈 확인

```sh
npm run check
npm run build
npm run audit:layout                                    # 전체(약 2분). 실패면 exit 1
npm run audit:layout -- --no-build --route '^home$'     # 고친 경로만 빠르게
```

- 결과 표: `.qa/layout/report.md`, 스크린샷: `.qa/layout/<상태>/<크기>/<경로>.png` (걸린 곳은 빨간 틀, 경고는 주황 틀).
- 상태: `new`(새 학생, 멘토링), `unknown`(새 학생, '아직 모르겠어요'), `example`(예시로 둘러보기), `onboarding`(가입 인터뷰 단계별).
- 고친 화면마다 **새 학생 · 예시 두 상태 × 1280×640 · 1440×900** 스크린샷 네 장을 직접 열어 본다(Read 로 이미지 보기). 장마다 자기 비평 한 줄: 무엇이 먼저 눈에 들어오는지, 빈 곳·넘침·잘림·어색한 줄바꿈이 있는지.
- 검사가 틀렸다고 생각되면(오탐) 화면을 고치지 말고 `scripts/audit-layout/probe.js` 를 고치자고 보고한다. `data-*` 예외 표시로 검사를 피하지 않는다.
- 목업(`docs/design/mockups/`)과 구성이 다르면 고치거나 이유를 적는다.
